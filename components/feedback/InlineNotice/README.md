# InlineNotice 内联提示条

用户填完一整屏表单，点提交，卡住了。问题不在某一栏，而是服务暂时连不上——这种「整件事出了状况，但你还有救」的说明，要贴在原地，让人慢慢读完再动手。

它是一条留在页面里的横条：一个状态图标、一句说明，右边还可能有一个关闭。网络不稳、配额快满、草稿存在哪儿，都是它。

## 什么时候用它

- 有一段状态说明需要一直看得见：网络不稳定、配额快用完、草稿存到了哪里。
- 整份表单提交失败，原因不属于任何一个栏位（服务超时、文件太大）。
- 一个设置改下去有副作用，需要在动手之前讲清楚。
- 页面还在用，只是某件事被降级了：缓存读取、离线模式、部分数据没同步上。

## 什么时候不要用它

- 一次性的成功反馈，说完就可以走：用瞬时提示，它不占页面位置。
- 需要用户在几个动作里挑一个（重试、忽略、查看详情）。提示条只有一个关闭，挑不了——改用带按钮的区域或者对话框。
- 某一栏填错了。错误要贴在那个栏位正下方，不要给每一行输入都套一条横条。
- 出了大事、需要用户立刻停下手上的活。它不抢焦点，也拦不住人——改用对话框。
- 一屏里堆了好几条。横条一多就变成背景噪音，宁可合并成一条，或者收进设置页。

## 怎么用得好

**颜色不是唯一的线索。** 几种语气在灰度下差别很小，色觉障碍用户未必分得出来。要么配一个图标，要么把状态直接写进文字里。

**说清「为什么」和「接下来怎么办」。** 「网络已断开」只交代了现状，「网络已断开，正在重试」才让人知道要不要动手。

**同一屏里只留一条。** 两条并排的提示条会互相削弱，用户不知道该先看哪条。真的需要并排，说明那是两件不同的事，应该分开说。

**关掉之后要留后路。** 用户点掉那条提示，信息就没了。如果这件事之后还得被找到，把结论同时留在页面上，或者留一个能重新打开它的入口。

**整条可点的时候，要说清点下去会怎样。** 可关闭的形态里，整条横条自己就是按钮，但用户从文字里看不出按下去会发生什么，得由名字补上。

**文案可能超过一行时，就选多行形态。** 它默认是一行、不换行，字长了会被裁掉，用户看到的是半句话。

| 语气 | 什么场合用它 |
| --- | --- |
| 信息 | 中性说明，没有好坏之分：保存位置、同步范围 |
| 成功 | 一件持续生效的事确认下来了 |
| 警告 | 现在还能用，但继续下去会出问题 |
| 错误 | 事情已经失败，需要用户决定怎么办 |
