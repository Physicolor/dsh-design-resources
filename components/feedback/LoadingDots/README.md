# LoadingDots 三点加载

用户按下回车，等回复。屏幕一动不动，他分不清是在生成还是已经卡住，于是又按了一次。只要有三个点在动，他就知道还没结束。

它是一行依次亮起的圆点，颜色跟着周围的文字走。用在位置确定、等待不长的紧凑地方。

## 什么时候用它

- 一次请求或一次生成正在进行，位置是确定的：紧跟在「正在生成回复」这类文字后面。
- 按钮内部短暂等待，或者工具条、状态行这种一行高的位置。
- 等待以秒计、估计不出进度，但用户还能接着做别的事。
- 一个动作已经发出、结果还没回来，需要让用户知道「收到了，在跑」。

## 什么时候不要用它

- 页面第一次加载、一大块区域还空着。三个点太小，占不住位置——改用骨架屏。
- 耗时可能超过几秒，而且进度估得出来。三个点不会告诉用户还要多久——改用进度条。
- 用户等待期间不能做别的。那是阻塞式加载，该给对话框或遮罩，而不是在角落里转三个点。
- 只是想说「这里是活跃的」。那表达的是状态，不是加载——改用状态圆点。
- 这件事可能失败，却打算让它一直转下去。转不停的动画对注意力障碍用户负担很重，失败时要给出出口。

## 怎么用得好

**让它一直动，别停。** 指示器一静止，用户就会以为进程卡死、应用没响应。真的卡住了，就把三个点换成一句说明加一个重试入口。

**别只给三个点。** 它说明「还在跑」，但不说明在跑什么。旁边配一句具体的话，比光转三个点有用得多。

**写清在做什么，别写「正在加载」。** 精确的描述才能让用户决定值不值得等下去。

**给读屏用户留一句话。** 三个点本身对读屏用户什么也不是，它需要一段看不见的文字被念出来，而且这句话可以按场景改写。

**它得能停下来。** 三点加载只有在自己消失时才有意义。如果这件事可能失败，请在同一个位置给出失败说明和重试入口。

**颜色跟着周围文字走，但要确认看得清。** 放在次级文字色里它会自动变浅，浅色主题下可能淡到看不见。

**它替掉一整块内容时，要说一声。** 列表正在加载，被替换的区域也要标出「忙」，否则读屏用户会以为列表本来就是空的。

| 要等的情形 | 用哪一种 |
| --- | --- |
| 一两秒，估不出进度 | 它 |
| 超过几秒，进度可估 | 进度条 |
| 一大块区域首次加载 | 骨架屏 |
| 等待期间不能做别的 | 对话框或遮罩 |
| 只想标「这里是活跃的」 | 状态圆点 |
