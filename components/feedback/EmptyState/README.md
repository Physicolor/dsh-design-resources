# EmptyState 空状态

用户第一次打开「已保存的搜索」，里面什么都没有。他不会想「这里是空的」，他会想「是不是坏了」——除非你在原地告诉他为什么空、接下来能做什么。

它是一块居中的说明：一个图标、一句标题、一段可选的解释，再加一个可选的动作。搜索没结果、列表还没建过、权限不够，都用它。

## 什么时候用它

- 列表或面板第一次打开，里面确实什么都没有。
- 筛选、搜索之后一条都没匹配上——这类文案要说明是筛选条件造成的，并给一个「清除筛选」的出口。
- 出错了但页面结构还在，用空状态加一个重试入口接住。
- 功能被权限或配额挡住，需要讲清原因和恢复办法。
- 用户删掉了最后一条，页面突然空了，需要一个重新开始的入口。

## 什么时候不要用它

- 数据还在加载。把「还没加载」画成「空」，用户会以为数据没了——改用骨架屏或者三点加载。
- 已经有内容，只是某个小块是空的。先想想这一块是不是该整个藏起来，空状态会占掉一大片竖向空间。
- 需要用户在两件以上的事里选（上传、导入、新建）。那是引导页的活；动作区里塞三个按钮，反而没人知道该按哪个。
- 一句话就能说清的错误。直接贴在原地当提示条，不用铺满一整屏。
- 只是这一屏暂时看不到。那要的是权限说明和升级入口，不是「暂无数据」。

## 怎么用得好

**标题要回答「为什么空」。** 「暂无数据」什么都没说；「还没有会话，问第一个问题试试」才让人知道下一步往哪走。

**最多给一个主操作。** 动作区里放那件最该做的事，其余收进次级样式。几个并列的按钮会让键盘用户不知道该按哪个。

**图标只是气氛，不是信息。** 它帮人认出这是空状态，但状态本身得靠文字说清。不要出现只有一个图标、一个字都没有的空状态。

**文案短到能一眼看完。** 标题一行，说明最多两行。再长就该回头想想，是不是这件事本身还没说清。

**它出现的时候，读屏用户也要知道。** 空状态常常是一次操作之后才冒出来的（点了筛选、删了最后一条）。这类异步出现的情形，需要让它被播报出来。

**别把「加载失败」和「真的没有」画成同一个样子。** 这两种空白，一个需要重试，一个需要开始。用同一块空状态接住，用户会去重新加载一个本来就空的页面。

| 什么场合 | 该给出什么 |
| --- | --- |
| 第一次打开，本来就没有 | 一句邀请，加一个开始的动作 |
| 筛选之后没有匹配 | 说明是筛选造成的，加清除筛选 |
| 加载失败 | 失败原因，加重试 |
| 没有权限 | 为什么看不到，加怎么获得 |
| 刚删掉最后一条 | 一个重新创建的入口 |
