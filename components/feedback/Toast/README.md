# Toast 瞬时提示

点了「保存」，页面看上去什么都没发生。文件其实已经存好了，可用户不知道，于是又点了一次。这类「事情做完了，却没有值得看的变化」的时刻，就该它出场。

它贴在窗口顶部居中，停留一会儿，然后自己淡走。复制成功、后台任务跑完、网络重新连上，都是它。

## 什么时候用它

- 事情已经做完，用户不需要再做任何一步：保存成功、复制成功、重新连上。
- 想要一点确认感，又不想在页面里永久占一块位置。
- 同一个动作被反复触发（连着保存几次），每次只需要一句短反馈。
- 动作本身几乎没有可见结果，用户需要一个「我点到了」的回声。

## 什么时候不要用它

- 用户需要读得久一点，或者需要动手（重试、查看详情）。它会自己走掉，用户还没读完就没了——改用内联提示条，那条会留在页面里。
- 表单里某一栏填错了。错误要贴在那个栏位旁边，不能飘到窗口顶上——那是内联提示条的活。
- 删除之前要问一句。这种确认得拦在用户面前，而它不接收点击、也放不下按钮——改用对话框。
- 同一时刻有好几条要说。它固定停在同一个位置，会互相盖住；宁可合并成一句，或者改用能排队的内联提示条。
- 页面第一次打开的欢迎语。那是静态内容，既不需要动画，也不需要倒计时。

## 怎么用得好

**只报结果，别拦人。** 它飘在内容之上，不接受任何点击，所以放在它身上的操作一个都点不到。凡是需要用户动手的事，换成内联提示条或者对话框。

**一句话说完。** 「已保存」比「操作已成功完成，你的更改已经保存在本地」好读得多。用户只是瞥一眼，不会逐字读。

**留给用户的时间要够读完。** 文案越长，停留时间就该越长。信息量大到需要读两遍，说明它本来就压不住这件事。

**只在成功时才出现。** 用户默认自己的操作会成功，只有不成功时才需要被告知。每次点什么都弹一条，很快就会变成没人再看的背景噪音。

**同一时刻只留一条。** 提示位只有一个，第二条会顶掉或者盖住第一条。连续动作只报最后一次，或者把几件事合成一句。

**它消失之后，界面上要有痕迹。** 深色底上的一行字，对读屏用户来说是一句会被立刻念出来的播报，这正是它的用处；但念完就没了。如果这件事之后还需要被查证，请把结果留在页面里。

| 什么场合 | 用哪一种 |
| --- | --- |
| 做完了，没有下一步 | 它 |
| 需要一直看得见的状态说明 | 内联提示条 |
| 不点个头就不能继续 | 对话框 |
| 内容还没回来、位置已知 | 三点加载 |
| 筛完发现一条都没有 | 空状态 |
| 位置空着，需要引导第一步 | 空状态 |
