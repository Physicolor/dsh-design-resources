# ListRowGroup 列表行组

上面一行小标题，下面一串排得整整齐齐的行，行与行之间只有一根细线。

设置页里「启动行为」下面那两条选项是它。右栏面板里「已连接的账号」下面那串账号是它。插件弹层里列出来的一批文件，也是它。

它解决的是长列表怎么读的问题：一屏里条目一多，用小标题把同类的东西圈在一起，用户扫的是标题，不用一行一行读完才知道这堆是什么。

## 什么时候用它

- 一串同类条目要放在一起：开关项、导航项、文件项、结果项。
- 这一串需要一个名字（「启动行为」「已连接的账号」），让人知道圈起来的是哪一类。
- 行与行之间想要一根细线而不是空隙，让一列条目看起来是一个整体。

## 什么时候不要用它

- 整行本身就是一次动作，需要按钮的样子和重量。请改用按钮，这里给的是列表的行，不是按钮的视觉重量。
- 一组里只能选一个。这里不表达「选中了哪一个」，请改用胶囊控件或开关。
- 是浮起来的下拉菜单。菜单有自己的卡片外观、阴影和上下键导航，这里都没有，浮层里请用菜单。
- 只有一两行，而且它们属于上面或下面那块内容。为两行加一个标题，标题会比内容还显眼。
- 一行里要放好几个能点的东西。整行可点和行内按钮会打架；把行留成不可点的排版行，操作放右侧。
- 设置项里「左边一个名字、右边一个控件」的那种表单行。那是设置行的活，这里的行是列表和导航语义。

## 怎么用得好

**分组的依据是用户怎么找，不是数据怎么存。** 「启动行为」下面放恢复与新建，「外观」下面放主题与字号——用户心里想的是「我要改哪一类」，不是这些字段在代码里属于哪个模块。一组里塞到六条以上就该重新想分组，标题一多就开始互相重叠。

**标题要说清这一类是什么。** 写「启动行为」，不要写「选项」「其他」。用读屏的人跳进这一组时，听到的就是这几个字，它得能独立成立。

**整行可点，就别在行里再放按钮。** 这是最常见的错：行变成一个大按钮之后，里面的小按钮既点不准，键盘也会卡在同一行里出不去。要么整行是一个动作，要么行只是排版、动作放在右侧。

**被截断的文字要能找回全量。** 文件名、账号名被省略号切掉，看得见的人读不全，用读屏的人却读得到——两边得到的信息对不上。让它在鼠标悬停时能看全，或者把能区分的那几个字留在行里。

**分隔线不表达层级。** 有线没线说明不了谁从属于谁，层级靠标题和结构说。另外两种画线方式只能用一种：让相邻行自动带上细线，或者自己插独立的分隔线，同时用会出现双线。

| 场景 | 行怎么设 | 为什么 |
| --- | --- | --- |
| 整行就是一个动作 | 整行可点 | 目标大，键盘也只停一次 |
| 行右侧挂着一个操作 | 行不可点，操作放右侧 | 避免两块点击区域打架 |
| 只是展示、点了也没事发生 | 行不可点 | 可点却什么都不做会骗人 |
