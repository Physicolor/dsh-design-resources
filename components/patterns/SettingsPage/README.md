# SettingsPage 设置页骨架

左边一列分区导航，右边一列内容。插件要提供一个完整的设置页时，用它搭架子。

插件设置页里左边列着「通用」「模型」「外观」，右边跟着当前那一段的表单——这套版式就是它。它不给任何控件定型，只决定导航放哪、内容放哪、标题多大。

它适合那种「用户可以不常来，但来了就想一次改完」的地方。

## 什么时候用它

- 插件自己有一个完整设置页，占的是整页空间，而不是嵌在宿主设置页里的一个小分区。
- 设置项多到需要左边的分区导航才扫得完。
- 内容列里反复出现「一个小标题 + 几行设置」的结构，想统一它们的样子。

## 什么时候不要用它

- 只是给宿主设置页加一个分区。宿主会给你一个已经排好版的容器，再套一整套骨架就变成两层导航。
- 只有一两个分区。直接用标题加列表行组就好，左边空着一列导航是浪费。
- 内容不是设置。会话语义的东西属于会话区，别借设置页的壳。
- 主流程里必经的一步。设置页是用户可以选择不去的地方，关键操作不能藏在这里。
- 只要一个区块的抬头。那用区块标题就够；整页骨架里的一级分区是另一回事，两者叠用会出现双层标题。

## 怎么用得好

**分区够多才值得要导航列。** 三个以上分区时，导航列帮用户先建立「这里一共几件事」的地图；两三个以下，导航列比内容还长，直接把标题堆在内容列里更快。

**一个分区只讲一件事。** 左边的名字、右边的标题、右上角的操作，说的得是同一件事。名字叫「通用」而里面混着模型参数，用户下次就不知道该点哪。

**内容列别铺满整屏。** 一行文字横跨很宽的窗口时，左边的名字和右边的控件离得太远，眼睛要在两头之间来回跳。给内容一个舒服的阅读宽度，剩下的留作留白。

**要标出「你在哪」。** 只靠底色区分当前分区不够，那点色差太细微。文字也跟着变深，再补上当前位置的语义标记，用读屏的人才知道自己站在哪一节。

**窄窗口自己收。** 骨架不做响应式折叠，因为它不知道宿主的断点在哪。窗口变小时，由你在自己的断点里把导航收成横向滚动，或者收进一个菜单。

**别抢用户的光标。** 页面打开、切换分区都不该把输入焦点从用户正在用的地方抢走。

| 场景 | 用哪个 | 为什么 |
| --- | --- | --- |
| 插件自己的完整设置页 | 整页骨架 | 分区多，需要一列导航 |
| 宿主设置页里的一个分区 | 宿主给的容器 | 再套一层就变成两层导航 |
| 一个区块的抬头 | 区块标题 | 骨架的一级分区是整页量级 |
| 会话语义的内容 | 会话区的容器 | 它不属于设置 |
