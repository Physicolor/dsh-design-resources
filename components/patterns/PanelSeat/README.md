# PanelSeat 会话区插槽容器

> 官方没有这个组件。下面是本仓库为插件作者准备的实现建议——它能用、数值逐条锚定官方既有选择器，但产品里并没有这个界面。

插件往对话流里插一块自己的内容时用的骨架：一行标题，标题右边一两个操作，下面是正文。

插件跑完一次构建，在回复下面贴一块「构建产物」，标题右边挂一个「复制」——这块就是它。它给插件一个说得过去的落点，插进来的东西有名字、有边界，不至于变成一串裸文字混在对话里。

它不抢焦点、不拦操作、宽度按内容收缩。插进来的东西应该像对话的一部分，而不是盖在对话上的一块面板。

## 什么时候用它

- 插件要在会话流里放一块自带说明的结构化内容：构建结果、引用来源、待确认的清单、插件自己的局部状态。
- 这块内容需要一个标题，而且标题右边有一两个操作。
- 内容宽窄不定，希望按内容收缩，而不是硬撑满整行。

## 什么时候不要用它

- 内容不是会话的一部分。全局设置、切换对象属于设置页和侧栏，别借会话流的壳把它们塞进来。
- 只是一句话的提示。用会自己消失的轻提示，或者一个静态标签，别为一行字套一个带标题的容器。
- 用户得先处理它才能继续。那是对话框和风险确认的活；这里默认不抢焦点、不拦操作，承载不了必经流程。
- 需要常驻可见、跟当前这段对话没什么关系的面板。那属于右栏，不该跟着对话滚走。
- 只是一段等宽的代码或输出。用代码块，它已经处理好了行号和横向滚动。
- 面板、抽屉、侧栏顶上那条标题栏。那是面板标题的活：它有固定高度，标题也不是标题元素；这里的标题是真的标题，宽度随内容走。

## 怎么用得好

**想清楚用户此刻在干什么，再决定要不要插。** 用户正在写下一句话时往会话里塞一块东西，就是在抢他的注意力。构建结果、引用来源这类跟刚才那一步直接相关的内容值得插；插件的启动信息、版本号不值得。

**插进来的东西要像一轮对话，不要像一块广告。** 对话是线性往下读的，所以默认透明底、不铺满宽度。一块两行字的提示占满整个消息区，会把上下文的节奏打断。确实需要独立纸面感时，才给它底色。

**一块内容只放一个标题。** 标题是这块内容的门牌，重复的标题会让人以为是两块不同的东西。同一段对话里插了好几块，标题之间要能区分：写「构建产物」，不要写「结果」。

**标题右边的操作要克制。** 一两个就够，而且是这块内容自己需要的动作：复制、重试、展开。需要用户先确认才能继续的，别塞在这里，改用对话框。

**不要抢走用户的光标。** 插件插内容的时候，用户可能正在输入框里打字。插入不该让输入焦点跳走，也不该自动弹出来挡住输入区。

**留白交给宿主。** 对话区里各行之间的距离由宿主统一控制，容器再加一圈内边距会叠成双层空当。只有带底色的形态才需要自己那圈内边距。

| 场合 | 插进去吗 | 为什么 |
| --- | --- | --- |
| 用户刚才那一步的直接结果 | 插 | 跟当前话题连着，用户正好要看 |
| 需要用户先确认才能继续 | 不插，改用对话框 | 这里不拦操作，会漏过去 |
| 插件的启动信息、版本号 | 不插 | 跟当前对话无关，属于右栏或设置页 |
| 常驻的状态面板 | 不插 | 那属于右栏，不该跟着对话滚走 |
| 一句话就能说完的提示 | 不插，改用轻提示 | 套一个带标题的容器太重 |
