# ToolbarRow 工具条行

> 官方没有这个组件。下面是本仓库为插件作者准备的实现建议——它能用、数值逐条锚定官方既有选择器，但产品里并没有这个界面。

一篇长文档读到一半，用户想跳回最上面；一张表格看完，想换个排序。这些「对眼下的内容做点小动作」的按钮，排成一行贴在内容边上，就是它。

它自己不是一个按钮，只是个容器：让里面的一排控件水平对齐、间距一致，需要的时候还能吸在顶部。

## 什么时候用它

- 一排并列的动作按钮：筛选、排序、格式化、刷新。
- 需要吸顶的工具条，滚到哪儿都停在上面。
- 浮在内容上方的悬浮工具条。
- 一段内容前后有好几件事可做，需要把它们归到一处。

## 什么时候不要用它

- 一组互斥选项（今天、本周、全部）。那是分段控件或者胶囊的语义，工具条不表达「选中了哪一个」。
- 只有一个动作。直接放一个按钮就好，不要为它套一层容器。
- 需要逐层展开的菜单。那是菜单的活，工具条不做菜单语义。
- 页面顶部那条完整的应用栏（带标志、搜索框）。那是导航栏，不是工具条。
- 可做的事多到一行放不下、还得靠读文字分辨。那说明该收进「更多」菜单，而不是把图标铺满一行。

## 怎么用得好

**一行别放太多。** 工具条是让人扫一眼就找到目标的，不是图标陈列柜。多到需要逐个读文字，就该把低频的收进菜单。

**能换行，但别指望它。** 窗口变窄时它会自动折到第二行，按钮不会被切掉；但折行之后原有的分组会被打散，真到这一步，主动收起来更好。

**按用途分组，组与组之间拉开距离。** 同一件事的几个按钮靠紧，不同用途之间空一格。全都等距排开，用户会以为它们是一类。

**浮起来的时候，底色和文字要配套。** 悬浮形态用的是深色半透明的底，上面的文字得跟着换成反色，否则浅色主题下直接糊成一片。

**吸顶就要说清边界。** 吸在顶部会盖住下面的内容，记得配一条分隔线或者一块底色，否则用户滚动时看不出内容从哪里开始。

**别给自己封一个工具条的名字。** 除非真的实现了用方向键在按钮之间移动，否则不要给它那层语义——说了做不到，反而是误导。

| 那排东西是什么 | 用哪一种 |
| --- | --- |
| 一组并列的动作 | 它 |
| 一组互斥的选项 | 分段控件或胶囊 |
| 只有一个动作 | 直接放一个按钮 |
| 分层展开的菜单 | 菜单 |
| 页面顶部的完整应用栏 | 导航栏 |
