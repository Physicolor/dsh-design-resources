# SidebarRow 侧边栏行

> 官方没有这个组件。下面是本仓库为插件作者准备的实现建议——它能用、数值逐条锚定官方既有选择器，但产品里并没有这个界面。

左侧栏排着几十条会话。用户扫一眼，要能认出哪条是自己的、哪条正开着、哪条里还有没读的消息——这些全得挤在同一行里，还不能显得挤。

它是一整行都能点的按钮：前面一个图标，中间标题，右边还能挂一个计数、一个快捷键提示，或者一个对勾。

## 什么时候用它

- 侧边栏里的会话、文件、页面列表项。
- 需要在列表项右侧挂一点状态：未读数、条数、快捷键提示。
- 需要标明「当前选中的是哪一条」的列表。
- 需要一次勾选多条（批量导出、批量删除）的列表。

## 什么时候不要用它

- 从按钮旁边弹出来的菜单项。那种菜单自带键盘导航和子菜单，不要自己搭一套。
- 只是跳到别处的普通链接。那用链接，按钮会丢掉「在新标签打开」这类浏览器自带的能力。
- 一行里要塞标题、说明、标签好几层内容。那种结构是给设置项准备的，用设置项行。
- 单纯展示、点不动的行。一个永远能点、点了却什么也不发生的按钮，是键盘用户的陷阱。
- 主要用途是「改一个值」。那是设置项行，它表达的是「改」，不是「去某处」。

## 怎么用得好

**一行只说一件事。** 图标加标题，再加最多一个尾部元素。右边同时挂计数、快捷键和对勾时，用户的视线会在三处来回跳。

**标题该截断就截断，别让它换行。** 一条换行的会话名会把整个列表的节奏打乱；截断虽然少几个字，但读屏用户拿到的仍是完整标题。

**选中的画法只用一种。** 尾部对勾适合和菜单保持一致，整行铺底色适合以扫视为主的列表。同一份列表里混着来，用户会以为那是两种不同的状态。

**多选行里的复选框别再套一层。** 行内那个复选框只是状态显示，点行里任何位置都能切换。再叠一层可以单独点的复选框，只会让人不知道该点哪个。

**一组可选中行要有个组名。** 不然读屏用户听到的是一连串孤立的按钮，不知道它们其实是一组互斥的选择。

**禁用就真的禁用。** 用原生的禁用方式，而不是把颜色调淡——调淡之后它还能被点到，也还能被 Tab 到。

**尾部挂的东西越少越好。** 一个计数或者一个快捷键就够。挂满一行小字，行与行之间就没有了快慢之分，用户扫视时会卡住。

| 这一行要干什么 | 用哪一种 |
| --- | --- |
| 在一组里选一条 | 它 |
| 一次勾选多条 | 它，用复选框形态 |
| 在一行里改一个值 | 设置项行 |
| 弹出菜单里的一项 | 菜单 |
| 跳到别处 | 链接 |
