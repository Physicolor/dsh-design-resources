# Switch 开关

设置面板里那一行「自动保存」，点一下就生效，不用再按保存——右边那个会滑过去的小开关就是它。深色模式、实验特性、开机自动更新，也是同一个控件。

## 什么时候用它

- 二态设置，改完立刻生效：自动保存、深色模式、实验特性。
- 用户点完就期待它已经生效，后面不必再按一次确认。
- 一行里讲一件事，标签写在左边，开关在右边，用户扫一眼就知道改的是什么。

## 什么时候不要用它

- 要按保存或提交才生效的表单：请改用复选框。开关的含义是「已经生效」，放在表单里会让用户以为改动已经落地。
- 两个互斥的选项里挑一个（列表还是网格、浅色还是深色）：请改用胶囊或分段控件，那是在选，不是在开。
- 点下去要发生一件事（删除、重试、立即同步）：请改用按钮。
- 只是展示状态、不让改：用标签或普通文字，不要摆一个永远灰着的开关。
- 一个开关统管一整组设置：说明层级没理清，要么拆成几个开关，要么换一种表达方式。

| 场合 | 用哪一个 |
| --- | --- |
| 改完立刻生效 | 开关 |
| 要按保存才生效 | 复选框 |
| 两个互斥选项里选一个 | 胶囊或分段控件 |
| 点一下执行一个动作 | 按钮 |
| 只读的状态 | 标签或文字 |

## 怎么用得好

**把「开的是哪件事」写在它旁边。** 开关自己不显示文字，用户只能从它左边那一行读出含义。孤立摆一枚开关，点的人只能靠猜。

**开关的开和关不能只差颜色。** 滑块滑过去、轨道换底色，两个信号一起给。只换颜色的话，色觉障碍用户看到的是同一枚开关的两种深浅。

**写入需要时间时，先说清楚再锁住。** 用户点完立刻看到它翻过去，如果之后失败又自己弹回来，会以为界面出了毛病。写入期间锁住并给一句悬浮说明，比「先亮后灭」诚实得多。

**别和复选框混着用。** 同一张表单里一半是开关、一半是复选框，用户读不出「哪个生效更快」。一个表单统一一种语义。

**这么小的一枚，鼠标也要够得着。** 开关的命中区比看起来大一圈，四周留出空隙，避免用户点到相邻那一行的开关上。
