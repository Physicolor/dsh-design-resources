# SegmentedControl 分段控件

文档列表右上角那个「列表 / 网格」，选完立刻换排布。图表上方那条「日 / 周 / 月」，也是它。几个短选项并排，当前那一段被填亮。

## 什么时候用它

- 选项不多、要一眼看全：视图切换、时间区间、对齐方式、单位。
- 选项少到不值得为它开一个下拉菜单，而且选完立刻生效、不需要再确认。
- 需要在同一行里表达「当前选中的是哪一个」，而单独一枚胶囊又太轻、撑不住这排选项时。

## 什么时候不要用它

- 选项太多，或者文案长度控制不住：请改用下拉菜单，横向空间会失控。
- 选项之间不互斥、可以一起选：请改用复选框组。
- 每一段会切换出一整块内容面板：请用标签页自己实现，分段控件不负责面板，硬套会让读屏播报出一块并不存在的面板。
- 点下去是一次动作（保存、删除）：请改用按钮，分段不表达「执行」。
- 只是标一个状态、点不动：请改用标签。
- 开和关：请改用开关，用两段的分段控件做开关是过度设计。
- 表单一开始可能什么都没选：分段控件看上去总有一段亮着，用单选项组表达「尚未选择」更诚实。

| 场合 | 用哪一个 |
| --- | --- |
| 几个互斥项，要一眼看全 | 分段控件 |
| 选项多、文案长短不定 | 下拉菜单 |
| 可以同时选好几个 | 复选框组 |
| 每一段对应一块会换掉的内容 | 标签页 |
| 只有两个状态、还要表达「已经生效」 | 开关 |
| 点一下就执行一件事 | 按钮 |

## 怎么用得好

**段数要克制。** 一排超过五段，用户就开始逐个读了，切换反而变慢。真的那么多选项，收进下拉菜单，或者改用可横向滚动的列表。

**每一段的字数尽量齐。** 一段两个字、一段八个字，整排会看起来歪向一边。文案压不齐时，把长的那段改短，而不是拉宽单段。

**同一条里别混着两种意思。** 一半是「切视图」，一半是「执行清空」，用户按下去才知道踩到了什么。分段表达的是「在这一组里选一个」，不是一排按钮。

**选中态不能只靠颜色。** 选中的那一段除了换底色，还有一圈内描边，灰度下也能看出形状差别。只用深浅区分，色觉障碍用户看不出当前是哪个视图。

**键盘要能一路走完。** 方向键在段间移动时，焦点和选中一起走；只有当前这一段是 Tab 的落点。中途断掉的话，键盘用户会被卡在半路。
