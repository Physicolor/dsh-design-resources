# Tag 标签

插件详情页那行小字——版本号、许可证、「已启用」——都是它。表格里每行末尾标着「构建失败」的红色小胶囊，也是它。

## 什么时候用它

- 给列表项、卡片或表格行补一小段元信息：版本、体积、运行环境。
- 给对象贴一个状态：已经上线、正在排队、上次运行失败。
- 在一组同类标签里，用最重的那一种配色指出当前选中的那一个。

## 什么时候不要用它

- 想让它能点：请改用胶囊。标签是只读的文字，点它什么都不会发生，也没有键盘落点。
- 表达开和关：请改用开关。标签说的是「现在是这样」，不是「可以改」。
- 承载动作（删除、重试、导出）：请改用按钮。给标签挂点击会造出一个键盘够不着的假按钮。
- 放一整句话：标签是一行不换行的小胶囊，长文案会把整行撑开，要么自己先截断，要么改用普通文字。
- 想让颜色自己说明一切：不行。绿色和红色在小部分用户眼里是一个颜色，文案里要写明「已启用」还是「构建失败」。

| 场合 | 用哪一种观感 |
| --- | --- |
| 一组里标出当前选中的那一个 | 最重的那种 |
| 中性事实，不带好坏 | 平台灰底 |
| 辅助到可以退到背景里 | 只留文字，不加底色 |
| 一切照旧、只想给个默认外观 | 细描边 |
| 已经跑通 | 绿 |
| 只是归类，不代表好坏 | 蓝 |
| 需要看一眼，但还没出事 | 琥珀 |
| 出事了 | 红 |

## 怎么用得好

**文案要比颜色先说明问题。** 标签一共就这么大，颜色只是加速器，真正要读的是那两三个字。「已启用」「构建失败」「待处理」都能独立读懂；只写「状态」两个字，配什么颜色都没用。

**一行里别堆太多。** 一排红黄绿挤在一起，用户会开始给颜色排序，而真正要传达的那个状态反而淹掉了。辅助性的那几枚退成无底色的样子，或者干脆写进正文里。

**同一个意思在整份界面里只配一种颜色。** 这里用琥珀表示「待处理」，另一个页面用琥珀表示「已归档」，用户就会开始怀疑颜色的含义，最后干脆不看了。

**别把标签塞进可点的整行里还指望它单独响应。** 标签是文字，焦点属于外面那一整行。用户点标签时，应该和点那行的其他地方效果一致。

**看久了眼睛会累。** 低对比的那两种观感适合辅助信息，不适合关键状态；关键状态要用对比更足的那些，读屏和弱视用户都更容易分辨。
