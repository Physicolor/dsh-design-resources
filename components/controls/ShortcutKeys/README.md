# ShortcutKeys 快捷键按键帽

> 产品里有这个东西：左栏「新会话」行尾那行 `Ctrl + Alt + N`、菜单项行尾的键位、工具提示里的小按键。几何是从产品客户端 CSS 模块里读出来的（`_keys_38b9q_1`），三种形态都有真值，见 SPEC。

它不是标签，也不是按钮：**它告诉你按什么键，自己不接受点击**。产品把它整个 `aria-hidden` 掉——键位对读屏是装饰，真正需要被念出来的是触发它的那个按钮上的 `aria-keyshortcuts`。

## 什么时候用它

- 按钮或菜单项有快捷键，把键位写在它行尾。用户会因此记住它。
- 工具提示里说明「按这个键更快」——用 `tooltip` 形态。
- 一组键要作为一个整体出现在密集的地方——用 `joined` 形态。

## 什么时候不要用它

- **没有真正实现的快捷键**。写了 `⌘K` 却按不动，比不写更糟。
- **按钮行尾之外的长处**。键位是辅注，不是正文；一行里出现两组以上，读者会去读它而不是读你让他做的事。
- **平排形态加底色**。那是提示气泡形态的样子；平排就是纯文字，加了底反而像一排小按钮（本仓库早前犯过这个错，已按采集值改正）。
- **拿它当标签用**。要标状态用 Tag，要点用 Pill / Button。

## 怎么用得好

**平时藏起来。** 产品在按钮行尾是 `opacity: 0`，hover / focus-visible 才出现——键位是给熟练用户加速的，不必常驻抢注意力。常驻会让每一行都多出一撮灰字。

**文字被挤到时渐隐，不要硬截断。** 产品的做法是给按钮文字加一层 `mask-image`，末端 16px 渐隐，让键位进来时文字自然让位。

**键位写法跟着平台走。** 产品用 `Ctrl` / `Alt` 这类文字键名而不是符号；同一界面里不要一半 `⌘` 一半 `Ctrl`。

| 形态 | 长什么样 | 用在哪 |
| --- | --- | --- |
| `plain`（默认） | 纯文字，键之间留 3px，`+` 独立一枚 | 按钮行尾、菜单项行尾 |
| `tooltip` | 每枚键一层浅底、11px | 工具提示里 |
| `joined` | 整组共用一层底 | 需要把组合键画成一个整体时 |

实现细节见 SPEC.md。
