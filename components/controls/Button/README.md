# Button 按钮

点一下就发生一件事。保存、发送、删除、重试——界面上所有「做完这步往下走」的地方，都是它。

右下角那个高亮的「发送」是它。对话框底部的「取消」和「确定」是它。工具条上一排不起眼的图标，也是它。

## 什么时候用它

- 触发一个动作：提交、保存、删除、打开一个菜单、重试。
- 一个动作比旁边的更重要，需要让用户一眼看出来。
- 工具条里排着一组动作，需要用不同的轻重把主次分开。

## 什么时候不要用它

- 只是跳到另一个页面。那是链接的活：按钮的意思是「执行」，不是「去某个地方」。
- 打开或关掉一个设置。那是开关。
- 在一组选项里挑一个。按钮不表达「选中了哪一个」，请改用胶囊或分段控件。
- 只是标一个状态。那是标签，标签点不动。
- 动作暂时做不了。直接把按钮置灰，别把它降级成次级样式——用户分不清「不能用」和「不是重点」。

## 怎么用得好

**一个界面里只留一个最重的按钮。** 满屏都是高亮按钮时，用户反而要花时间比较哪一个才是主路。一个视图里留一到两个就够，最重要的那个给最重的样式。

**别用大小来分主次。** 两个一样大的按钮并排，用户会当成一组平级的选择；一大一小并排，看起来像没对齐。要突出首选，改样式，不要改尺寸。

**文字要能独立读懂。** 「保存」「删除这条会话」都行，「确定」尽量少用——脱离对话框就看不出在确定什么。图标按钮要配一句能被读屏念出来的说明，否则读屏用户听到的是一片空白。

**按钮要有按下去的样子。** 按下完全没有反应，用户会怀疑是不是没点上，然后反复点。

**挨得太近会点错。** 两个按钮之间留够空隙，触摸设备上尤其明显。排在行里的小按钮和相邻内容之间也要留余量。

**做不了的按钮要看得出来做不了。** 置灰之后仍然占着位置，用户知道这里以后能点；直接藏起来会让界面跳一下。

| 变体 | 什么场合用它 |
| --- | --- |
| 实心强调 | 这一屏最重要的那一个动作：保存、确认、发送 |
| 无底色 | 默认样式。次级操作、工具条里的文字按钮 |
| 带描边 | 需要跟实心按钮拉开层次，比如对话框里的「取消」 |
| 半透明底 | 浮在内容之上的工具条 |

| 尺寸 | 什么时候用 |
| --- | --- |
| 标准 | 常规页面、对话框页脚 |
| 紧凑 | 密集的列表行、卡片角上的小操作 |

同一屏里别把两种尺寸混着放，除非它们在结构上真的属于两层。
