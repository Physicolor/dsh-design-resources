# Drawer 抽屉

> 官方没有这个组件。下面是本仓库为插件作者准备的实现建议——它能用、数值逐条锚定官方既有选择器，但产品里并没有这个界面。

从右边出来的一块面板：文件树、会话详情、插件信息、检查器。用户还看得见身后的页面，只是暂时碰不到它。

它是「别离开这一页」和「别打断我」之间的折中——比对话框宽，比新开一页轻。

## 什么时候用它

- 需要一块附属内容，但不想让用户离开当前页面：文件树、会话列表、插件详情、检查器。
- 内容比对话框长、要滚动，又不至于单独占一页。
- 右侧的工具面板，或者从左侧进来的导航式面板。

## 什么时候不要用它

- 短决定。用对话框：它居中、宽度受控、注意力更集中。
- 常驻导航。抽屉会盖住内容，常驻的侧栏该直接占位置，不压遮罩也不拦点击。
- 用户要填一整套表单。抽屉的宽度放不下长表单，改用独立页面。
- 只是想推一句消息。用提示条。
- 一次开好几个抽屉。遮罩会互相盖住，焦点也会打架，改成在抽屉里换内容。
- 用户只是路过看一眼、不需要做任何事。这种时候遮罩是白付的打断成本，把那块内容直接放进页面更划算。

## 怎么用得好

**抽屉是临时层，不是第二块页面。** 用户按一下 Escape 就回到原处，所以只能在这里读到的关键信息等于没有。要留下的东西放进正文。

**宽度只够放一列。** 放得下一列设置项或者一棵树就够；再宽就又变成一页，还平白压掉了正文的宽度。

**让内容在里面滚，底部动作留在外面。** 面板的高度是固定的，长内容自己滚；底部操作跟着一起滚走，用户就得翻到底才能按。

**方向跟着直觉走。** 检查器、详情、设置这类从右边来；导航、目录这类从左边来。同一个入口每次换边，用户会怀疑自己是不是点错了。

**同屏只留一层遮罩。** 抽屉和对话框叠在一起时，用户不知道自己按 Escape 会关掉哪一层。

| 什么时候 | 用哪一层 |
| --- | --- |
| 短决定，用户得先回答 | 对话框 |
| 长内容，用户要边看边翻 | 抽屉 |
| 内容要一直看得见 | 常驻侧栏 |
| 只是一句话的告知 | 提示条 |
