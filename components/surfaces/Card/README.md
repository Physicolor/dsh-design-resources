# Card 卡片

> 官方没有这个组件。下面是本仓库为插件作者准备的实现建议——它能用、数值逐条锚定官方既有选择器，但产品里并没有这个界面。

会话统计、插件详情、空状态说明——页面上那些自己成一体的信息块，都是它。设置页里那张写着「上下文占用」、旁边标着已用多少的小卡片，就是最典型的用法。

它是一张贴在页面上的纸：一圈浅浅的边，一层比背景稍亮或稍暗的底色。它不浮起来，也不表示「点我」。

## 什么时候用它

- 一组相关信息要看起来是一件事：统计摘要、设置分组、插件详情、空状态说明。
- 页面上并排摆着几块内容，得让人一眼看出哪块到哪块为止。
- 结构固定——标题、一句说明、正文、底部一个动作——又不想每处都重新调一遍间距。
- 想让标题和正文之间有一眼可辨的层级。

## 什么时候不要用它

- 要浮在页面之上。那是对话框、抽屉和菜单，它们用投影说「我浮着」；卡片是贴地的，只有一条细边。
- 排成一长串的同类条目。改用一行加一条细分隔线：一排卡片读起来像一堆并列的盒子，而不是一条能顺着往下读的列表。
- 整块要能点。卡片本身没有「点我」的意思。要整块跳转，就把内容放进链接或按钮，或者把动作放到卡片底部。
- 只是想要一块底色。直接给容器上底色就行，套一层卡片只会白白多出一条边。
- 卡片里再套卡片。两层边线会把间距读乱，里面改用小标题加留白。
- 只想把两个区块分开。那是区块表头的活。

## 怎么用得好

**标题写清这块是什么，不要写「详情」。** 用户在长页面上是扫标题的，标题含糊，这张卡片就等于不存在。

**说明是补充，不是正文。** 说明用的是更浅的颜色、更小的字，是最容易被跳过的一行。唯一的状态提示塞在这里，等于只有细看的人才看得见。

**没有内容就别放卡片。** 一个只有边线的空盒子比这里什么都不放更糟，用户会以为内容没加载出来。

**一张卡片放一件事。** 相关不等于同一件。两个不相干的小结各占一张，读者才知道该先看哪张。

**并排的卡片，标题长度对齐。** 长短不齐会让同一行卡片看起来不一样高，读者会当成两组东西。

**底部只留一个最重的动作。** 卡片底部是收尾的地方，两个一样重的按钮会让用户停下来比较。

| 场合 | 这一层怎么表达 |
| --- | --- |
| 页面里自成一体的信息块 | 用卡片 |
| 浮在页面之上、要盖住内容 | 用对话框、抽屉或菜单 |
| 一长串同类条目 | 用行加细分隔线 |
| 只是想要一块底色 | 直接上底色 |
| 能展开收起的分组 | 用折叠行 |
