# Modal 对话框

点了「删除会话」之后，屏幕正中弹出来问一句「确定吗」。用户得先回答，才能往下走——这是它唯一存在的理由。

一层遮罩把后面的一切压暗，一张卡片浮在正中。它替产品说了一句「先停一下」。

## 什么时候用它

- 用户得先回答一句才能继续：确认创建、给会话起个名字、选一个保存位置。
- 一个动作做错了收不回来，要用户明确点头。
- 出错了，需要用户当场决定重试还是放弃。
- 一处内容要独占注意力，而且只占一小会儿。

## 什么时候不要用它

- 只是告知。用提示条，通知不该拦住用户手上的事。
- 内容长、要滚动阅读。改用抽屉或独立页面，对话框适合短决定。
- 二选一而且不用解释。就地放两个按钮，不必抬一层遮罩。
- 同一件事会反复发生。每次弹一下都会打断节奏，改成行内表单或者就地确认。
- 用户正在打字、正在选中内容、正在读一段东西。除非这一步真的走不下去，别打断——打断的代价是他忘了刚才在干什么。
- 在对话框上再开一个对话框。改成在框内换内容，不然用户会忘记自己是从哪一层进来的。

## 怎么用得好

**每一层遮罩都要付利息。** 打断是有代价的：用户被带离原来的位置，关掉之后还得重新找回思路。只在打断确实帮到他时才用。

**标题就说这件事叫什么。** 用户从暂停里回来，靠标题认路。写成「确认」等于没说。

**按钮写动作，不写「确定」。** 「删除这条会话」比「确定」多几个字，但用户按下去之前知道自己按的是什么。

**给一条明确的出路。** 键盘上的 Escape、点遮罩、右上角的关闭，三条都要在。为了「强制用户选择」把它们拿掉，用户只会更慌——强制流程的问题出在流程本身，不在这个出口。

**如果关掉会丢东西，先问一句。** 用户辛苦填的内容，不该因为点了一下旁边就消失。

**别让对话框里一按回车就提交。** 误触的代价在这一层会被放大。

| 什么时候 | 用什么 |
| --- | --- |
| 只是告知，用户不用做决定 | 提示条 |
| 用户得先回答才能继续 | 对话框 |
| 内容长、要滚动阅读 | 抽屉或独立页面 |
| 二选一、无需解释 | 就地的按钮组 |
| 会反复发生的操作 | 行内表单 |
