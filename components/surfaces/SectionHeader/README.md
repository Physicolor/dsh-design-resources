# SectionHeader 区块表头

设置页里每一组设置的抬头：一行「模型」，下面一句「选择默认使用的模型与推理强度」，再收一条细线。用户扫一眼就知道接下来这几行归哪一类。

## 什么时候用它

- 设置面板里，把一组相关选项和一句标题对齐。
- 长表单要分段，每一段都得有一句话交代这组是干什么的。
- 内容区想跟导航或页面标题拉开层次，靠一条细线而不是靠把字加粗加大。

## 什么时候不要用它

- 对话框顶部的标题。那是对话框自带的一行，层级和间距都不一样；混用会让用户分不清自己还在原页面，还是已经进了新的一层。
- 卡片内部的标题。改用卡片自己的标题位：区块表头是给页面分段的，塞进卡片里会把层级顶破。
- 要能点开收起的分组。那是折叠行的活——标题得能点，还得带展开与收起的痕迹。
- 只想画一条分隔线。那就画一条线或者留白，别为了画线塞一个空标题进去。
- 页面主标题。一个页面只有一个主标题，那是页面自己的事。

## 怎么用得好

**标题说这一组管什么。** 只写名词等于没写：用户看到「高级」不知道高级在哪。写「历史消息如何压缩」比写「上下文」有用得多。

**副标题只放补充。** 它是最小、最浅的一行，低视力用户最难读。像「此操作不可撤销」这种关键约束，要放进正文或者用状态色说出来，不能只藏在副标题里。

**分隔靠留白，不靠那条线。** 细线是段落的句号，不是唯一的墙。两组之间没有足够留白，用户会把它们读成一整块。

**同一深度的抬头，级别要一致。** 一页里同一个层级的小节用同一档标题；跳级会让读屏用户的跳转目录错乱。

**表头自己不带外边距。** 上下间距交给整页统一的间距档，否则两处表头之间的呼吸会各不相同。

| 场合 | 抬头用哪个 |
| --- | --- |
| 设置页里的一组选项 | 区块表头 |
| 对话框顶部 | 对话框自带的标题行 |
| 卡片内部 | 卡片的标题位 |
| 能展开收起的分组 | 折叠行 |
