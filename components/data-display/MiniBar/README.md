# MiniBar 迷你条形图

一条横着的小轨道，填到哪儿就表示「占了多少」，塞在列表行里也不占地。

上下文窗口用了多少、磁盘还剩多少、这个任务跑到第几步，都可以用它在旁边画一条。它常和指标行搭班：指标行给名字和数字，它在旁边把同一个数字变成一段长度。

它只回答一个问题：离满还有多远。

## 什么时候用它

- 列表行里表达占比：上下文占用、缓存命中、磁盘使用、任务进度。
- 和指标行搭班，给同一个指标补一个能一眼比较的视觉量。
- 想让用户立刻看出「快满了」。

## 什么时候不要用它

- 几组数据横向比长短。那需要一组共用基线的条形图，这里只有一条轨道。
- 数字本身已经够用、比例没有意义。多出来的一条是噪声。
- 需要用户拖着改数值。这是只读的展示元素，不是滑块。
- 需要读出精确数字。条形旁边的百分比是取整过的，精确值请写在旁边的文字里。
- 表达一个开关的开与关。长度表达的是程度，开关表达的是两个状态，请改用开关或状态圆点。

## 怎么用得好

**旁边的文字才是读数的地方。** 条形负责「大概占了多少」，精确值交给旁边的数字。只画条不给数，用户没法引用它，也没法把它抄进工单。

**一条轨道只配一个数字。** 想让用户比较两条，就上下排好、共用同一个满值。两条各有各的量程时，长度不可比，看起来却像可比——这是最误导人的一种排法。

**越接近满越要说话。** 快到上限时换一种颜色提醒，同时在文字里也说出来。颜色变了用户未必知道是什么意思，看不清颜色的人更是完全收不到这个信号。

**给条形一个名字。** 一条光秃秃的轨道，用读屏的人只会听到一个没有主人的进度，不知道说的是哪个指标。

**量程要能退化。** 超出上限的值按上限算，分母为零的场合别显示成「零」——那是「算不出来」，要在文字里说清楚。

| 场景 | 用哪个 | 为什么 |
| --- | --- | --- |
| 一个指标占了多少 | 迷你条形图 | 只有一条轨道，表达单值比例 |
| 几组数据比长短 | 条形图 | 需要共用基线 |
| 只要一个精确数值 | 指标行 | 条形旁边的百分比是取整的 |
| 让用户拖着调数值 | 滑块 | 这里是只读展示 |
