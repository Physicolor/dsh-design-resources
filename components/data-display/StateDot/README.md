# StateDot 状态圆点

一个小圆点，用颜色和形状说「成了、出问题了、还在跑」。

构建结果列表里每一行左边那个点是它。时间线上一串任务各自的标记是它。会话标题旁边表示「还在生成」的那个会动的小方块，也是它。

它是个标记，不是句子——旁边得有文字把话说完，圆点只负责让一列状态对齐、扫的时候快。

## 什么时候用它

- 列表行、时间线、步骤条左侧的状态标记。
- 任务、会话、工具调用的运行状态：还在跑、成了、有警告地成了、失败了。
- 需要在同一列里纵向对齐，并且希望颜色跟着主题走。

## 什么时候不要用它

- **单独用。** 它对读屏软件是完全隐身的，屏幕上只有圆点没有文字时，用户什么也听不到。没有文字可配时请用标签，或者带文字的连接状态指示器。
- 表达开关或者可点击的选中态。那是开关和胶囊控件的活，圆点点不动。
- 表达进度。圆点只有几个离散的状态，说不出「跑到一半」，请改用迷你条形图。
- 表达文件类型。那是文件类型图标的活。
- 在永远只有一种状态的地方当装饰。那是纯装饰，写个样式就行，不必搬来一个组件。

## 怎么用得好

**圆点旁边得有文字。** 它顶多算个形容词，句子还得由行里的文字说完：写「构建失败」，别只留一个红点让人猜。它同样扛不住灰度——成功和空闲两种颜色挨在一起时，只看颜色的人分不出来。把结果写进文字，圆点负责让一列状态对齐、扫得快。

**只有「还在跑」可以一直动。** 那个转圈的方块是唯一允许持续动画的状态，因为它表达的正是「正在进行、还没有结论」。其余状态都不要加动画：一个不动的东西说自己还在跑，用户会以为卡住了。

**别指望放大圆点来强调。** 尺寸变大不会让它更被注意到，反而会跟旁边的文字对不齐。要强调，就把文字写重一点，或者干脆用标签。

**「空闲」不是第四种结果。** 它的颜色刻意比另外三种淡，意思是「这里没事发生」。如果它出现得太频繁，说明这一列里混进了不该标的东西。

**放进行首时，自己确认它跟文字对得齐。** 放大只改外圈，里面的实心核按比例跟着变，圆点本身不会变形。但它和同一行文字的行高对不对得上，官方没有给过默认尺寸之外的用例，得实际看一眼再定。

| 场景 | 用哪个 | 为什么 |
| --- | --- | --- |
| 一列任务的状态 | 状态圆点 | 状态是离散的几个，圆点最省地方 |
| 开关的开与关 | 开关 | 要能点，还要表达当前状态 |
| 跑到一半 | 迷你条形图 | 进度是连续量，圆点只有几档 |
| 一个静态的分类标记 | 标签 | 标签自带文字，圆点没有 |
