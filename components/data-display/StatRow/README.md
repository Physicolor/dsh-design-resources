# StatRow 指标行

左边一个名字，右边一个数字，一行一行对齐下去，扫一眼就能读数。

面板底部那行「缓存命中率」和它右边的数字，是它。会话详情里的「首字延迟」，模型摘要里的「上下文窗口」，也是它。

一排指标行摆在一起时，用户的视线会沿着右边那列数字往下滑，去找那个变大、变小、或者跟印象对不上的一个。

## 什么时候用它

- 一屏里要同时交代好几个只读的指标，用户按名字去找其中一两个。
- 除了当前值，还想让用户看到它相对基准的变化：涨了、跌了、还是没动。
- 面板里要纵向排一列数字，希望列与列对得齐、行距一致。

## 什么时候不要用它

- 只有一个数字，而且这个数字是整块区域的主角。指标行用的是正文大小的字号，撑不起大屏读数，请用专门的统计卡片。
- 数据是一组「名称 → 值」的自由明细，值可能很长、会换行。请改用键值列表，它给名称留了固定的一列。
- 需要用户填进去或者选一下。这里是纯文字，点不动，也进不了键盘焦点。
- 想用一根横条表达「占了多少」。那是迷你条形图的活，把它接在数值后面。
- 数值要和别的对象逐个对比、还要能排序。那是表格的活。

## 怎么用得好

**先排用户想找的那一个。** 一列指标行是从上往下读的，排在最上面的一行默认最重要。别按数据在系统里产生的顺序排，按用户打开这块面板时最想问的问题排：先「还够不够用」，再「快不快」，最后才是次要的计数。

**数字要比名字显眼，但只显眼一档。** 名字小一号、浅一档，数字用正文大小和最深的颜色。反过来的话，用户会先读到一串名词，还得自己在脑子里配对。数字再放大一档就抢了标题的位置，也不对。

**变化量要自带符号。** 只把变好的那行染成绿色，分不清颜色的人读不出方向，用读屏的人更是只听到一个孤零零的数。写成带加号或减号的文本，颜色只当加强。

**单位贴着数字，别塞进名字里。** 「首字延迟」的右边跟一个「毫秒」，比在名字里写「首字延迟（毫秒）」好读。名字那一栏一旦出现括号，用户就得在两段文字之间来回对。

**只给名字和数值也是一种用法。** 一排这样的行落在一起，右边自然对齐成一列数字，看起来已经够整齐，不必再加装饰。

| 场景 | 用哪个 | 为什么 |
| --- | --- | --- |
| 一屏里好几个只读指标 | 指标行 | 名字与数字分列对齐，方便自上而下扫读 |
| 只有一个大数字 | 统计卡片 | 指标行的字号是正文级，撑不起主角 |
| 长短不齐的键值明细 | 键值列表 | 值可能很长，需要换行 |
| 占了多少 | 迷你条形图 | 长度比数字更容易一眼比较 |
