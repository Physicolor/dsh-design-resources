# KeyValueList 键值列表

> 官方没有这个组件。下面是本仓库为插件作者准备的实现建议——它能用、数值逐条锚定官方既有选择器，但产品里并没有这个界面。

一列「名称 …… 值」，名称对齐在左边，值可以很长、自己折行。

模型参数面板里那张「模型 / 上下文窗口 / 温度」的清单是它。请求详情里逐条列出的头部信息是它。文件信息里的「路径」「大小」「修改时间」也是它。

它回答的是「这东西由哪些字段组成」。用户会从上往下逐条读，或者挑其中一两条抄走。

## 什么时候用它

- 展示一个对象的只读明细：模型参数、请求头、配置摘要、文件信息、环境变量。
- 名称是固定的短词，值可能很长——一长串路径或网址会自己折行，不会把容器撑破。
- 想纵向比一列数字，让值贴住右边，小数点能对上。

## 什么时候不要用它

- 只有一两行，而且重点是那个数值本身。请改用指标行，它的数字更醒目、语义也更窄。
- 用户需要编辑这些字段。这里是只读的说明结构，请用输入控件。
- 值是列表、树、代码块这类成块的内容。放是放得下，但会被行距压扁，请改用自定义卡片。
- 名称和值是平级的并列项，没有主从关系。用表格或标签列表，这里的结构表达的是「名称 — 描述」配对。
- 同一批字段要在多个对象之间横向对比。那是表格的活。

## 怎么用得好

**名称短、值长，是它最舒服的形态。** 名称那一列按内容取宽，值那一列吃掉剩下的宽度。名称一旦写成一句话，值就被挤得换行，整块看起来像段落而不是清单。

**值该折行就让它折。** 长路径和网址截断成省略号看着整齐，但用户复制不到完整内容，也确认不了对不对。宁可多占一行。

**值的颜色要比名称深。** 用户靠深浅分出「哪边是我要读的」。只靠左右位置区分，眼睛会一直来回找。

**同一组里的字段按用户认得出的顺序排。** 先身份（模型、路径），再规格（窗口、温度），最后是时间。别按代码里的字段顺序排，那个顺序只对写代码的人有意义。

**需要给整组起名时，在外面加一个标题。** 别把名字塞进第一条键值里假装是表头，那会让这一条看起来和别的不一样。

| 场景 | 用哪个 | 为什么 |
| --- | --- | --- |
| 一个对象的只读字段 | 键值列表 | 名称定宽、值可折行，长内容不溢出 |
| 只有一两个指标要强调 | 指标行 | 数值更醒目，语义更窄 |
| 一批字段横向比多个对象 | 表格 | 需要跨对象对齐成一列 |
| 值本身是列表或代码 | 自定义卡片 | 块级内容要自己的间距 |
