### 不通过项（有证据）

**A1. 输入卡「圆角 28px」是错的，实测 21.4px。**
证据：`docs/reference/01-hero.png` 是 1570×905 的 1:1 整屏截图。卡片外框在 x 531..1312、y 445..560，左上角圆弧逐行内缩序列为
`dy=0..20 → inset=21,15,12,10,9,8,6,6,5,4,3,3,2,2,2,1,1,1,1,1,0`。
最小二乘拟合：**r = 21.4px（RMSE 0.42）**；`r=21` RMSE 0.46；`r=22` RMSE 0.52；**`r=28` RMSE 3.68**。r=28 在弧线中段系统性高估内缩 3.5–5.6px。
另外：`geometry.json` 全树出现过的 `borderRadius` 只有 `0px / 8px / 12px`，**没有任何 28px**；也没有任何节点宽度接近 780。
写成 28px 的地方共 6 处：`website/shell/shell.css:61`、`:418`、`:433`、`website/shell/parts/composer.js:6`、`website/shell/data.js:64`、`docs/reference/README.md:66`。
`docs/reference/README.md` 第 42-65 行的表每行「来源」列都点名一个 `*_节点`，**只有第 66 行没写节点**，写的是「直接量 `[data-input-scroll]` 的父元素」——唯一没有采集物支撑的一行，正好是估错的那一行。
根因：`scripts/capture-dsh.mjs:79` 是 `if (depth > 9 || nodes.length > 3000) return`。`Dc7zOa_composerSeat` 恰好落在 d=9，卡片是它的子节点，**整棵子树从没进过 geometry.json**（51 个节点里 d 的最大值就是 9），于是这个数只能手量，手量量错了。
修：`--sh-radius-card: 21px`；`README.md:66` 的圆角改 21px 并把来源写成「01-hero.png 像素测量（geometry.json 深度上限 9 未覆盖）」；`capture-dsh.mjs` 给 composer 子树单独放宽深度。

**A2. 卡片边框挪用了 newSession 的值。**
`shell.css:432` `.sh-card { border: 1px solid var(--sh-line) }`，而 `--sh-line = rgb(0 0 0 / 12%)` 的出处注释（43 行）明写是 newSession 的边框。
实测卡片边框像素 `(236,236,236)`，叠在白底上透明度 ≈ **0.075（约 7.5%）**，渲染出来是 `#ECECEC`；12% 会渲染成 `#E0E0E0`。这正是「把不同节点的值混在一起」。
修：新增 `--sh-line-card: rgb(0 0 0 / 7%)`，注释写明「卡片实拍 236/255」，卡片用它。

**A3. `--sh-right-w: 348px` 找不到出处。**
`shell.css:50` 注释「右栏默认收起，打开时 348px」。geometry.json 里唯一的右侧节点是 `OUqwTW_panel rect [863,0,707,905]`（宽 707），而 `docs/reference/README.md:68` 明确说那是**插件**面板、复刻官方骨架时不计入。348 在任何采集物里都不存在。
修：要么补一次真实右栏的采集，要么把注释改成「示例值，未采集」。

**A4. 少了一个 4px 间隙，整列往下偏 4px。**
geometry.json：`logoRow` 底边 y=66，`newSession` 顶边 y=70 → 中间有 **4px**。`shell.css` 的 `.sh-logo`(131-138) 没有下外边距，`.sh-new`(175) 直接跟上，间隙为 0。
实测（`docs/screenshots/site-frame-layout.png`，shell 内部纵向是 1:1）：新会话按钮边框盒 y=828..865（白底 829..864），而产品同一起点应为 832..869。**偏高 4px**，后续 panelList 等一并偏 4px（shell 878 vs 产品 882）。
修：`.sh-logo { margin-bottom: 4px }`（或给 `.sh-panels` 的 margin-top 从 12 改 16 并说明）。

**A5. 「保持真实比例」在它实际渲染的宽度下不成立。**
`shell.css:89-91` 用 `width:100%` + `aspect-ratio: 1570/905`，但 `--sh-side-w` 是**固定 280px**，不随容器缩放。`verify.mjs` 自己报出 `{"root":888,"side":280,"center":607,"head":40}`：
- shell：左栏占 280/888 = **31.5%**
- 产品：左栏占 280/1570 = **17.8%**
像素复核：`site-frame-layout.png` 里导轨底色 `#f9fafb` 实际画在 x=313..591（279px），shell 根约 x=312..1199（888px）→ **31.4%**。`shell.css:91` 注释「采集视口，保持真实比例」与它自己的输出矛盾。
全仓库没有任何文档说明「只在容器宽 1570px 时忠实」。
修：给 `.sh-side` 用 `width: calc(var(--sh-side-w) * var(--sh-scale))`，或加一层 `transform: scale()` 容器，或至少在注释里写明该限制。

**A6. 无出处的数值（没有 `←` 注释，geometry.json 也没有对应节点）。**
`.sh-session height:30px`(269)、`.sh-msg__bubble` 的 `16px` 圆角与 `#f2f3f5`(390-398)、`.sh-tool` 的 padding(407-416)、`.sh-flow` padding(382)、`.sh-right` 系列(513-531)。
原因是几何采集的深度上限把会话行、消息气泡全丢了（`_9lTDKa_listArea` 在 d=9，子节点全部未采），这些值属于「凭源码想象」。

### 检查漏洞（比实现漏洞更值得说）

1. **`website/verify.mjs` 从不读 `docs/reference/geometry.json`**（grep 该文件对 `geometry` 零命中）。所谓「复刻」与「基准」之间**没有任何自动化联系**——注释里写什么、写错什么，检查都不会响。
2. 与 shell 几何有关的断言只有 4 条：`verify.mjs:383` 左栏 280px、`:384` 头 40px、`:385` 至少 3 条会话、`:441` 改宽度能生效。
   - 断言的是**绝对 px 值**，所以 A5 那种「宽度比例错一倍」它必然通过（280 在 888 宽的容器里也等于 280）。
   - 面板行 252×36、拖拽带 8px、输入卡尺寸/圆角、logo→newSession 间隙，**一条都没检查**。
3. 没有任何一条检查比对 `shell.css` 注释与 geometry.json 的数值。A1「28px vs 21px」这种错误，绿灯体系下可以长期存在。
4. 建议加的最小检查：解析 `shell.css` 里所有 `← 节点` 注释，去 geometry.json 按类名取 `rect`/`style` 比对，不符即红；再加一条「`--sh-side-w` 占容器宽的比例与 280/1570 的偏差 <2%」。

## 我认为这个仓库仍然在骗人的地方

1. **座位占用数字（14/13、11/3/order 40、三个点名 bundle）。**
   写作「已核实事实」「[实测]」「来自对运行中的 Harness 逐条清点，不是估算」，实际全仓库找不到任何快照、脚本或数据能复现它，`data/raw/slot-tree-2026-10-01.json` 里这些名字出现 0 次。它未必是编的，但它**被当成了已验证事实来用**，而这正是用户上一次批评的那种东西。这是我认为最严重的一处。

2. **输入卡「圆角 28px」。**
   在 6 处被写成「实测」，其中 `docs/reference/README.md:66` 是全表唯一没写采集节点的一行。仓库自己附带的那张 1:1 截图量出来是 **21.4px**（r=28 的拟合误差是 r=21 的 8.8 倍）。即：**基准截图就在仓库里，结论和它对不上，还被标成实测。**

3. **`shell.css:91` 的「保持真实比例」。**
   同一份 CSS 里 `--sh-side-w` 是固定 280px，于是站点实际渲染（888px 宽）时左栏占 31.5%，产品是 17.8%。`docs/screenshots/site-frame-layout.png` 里画出来的就是这个 31.5%。注释宣称忠实，产物不忠实，且没有任何文档交代这个限制。

4. **（次要但同类）`--sh-right-w: 348px`** 标着「打开时 348px」，采集物里根本没有这个数，唯一相关的 707px 还被 README 明确排除在外。
