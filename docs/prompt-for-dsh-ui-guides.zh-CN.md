# 给 DeepSeek Harness 的界面规范维护任务

请基于当前仓库和运行中的 DeepSeek Harness，审阅并维护这套面向社区插件作者的界面设计规范。目标是让作者能按真实 DSH 窗口找到控件，理解用途、状态、尺寸来源、扩展位置和可复用实现。

## 先建立实景依据

1. 先阅读仓库说明、规范、指南、组件目录、元素清单、来源记录和 docs/reference/README.md。
2. 对每个计划展示的界面示例，先找到 docs/reference/ 中对应的真实 DSH 截图；缺少对应场景时，用只读采集方式从运行中的 DSH 拍摄，并把截图展示给用户审阅后再改 HTML。
3. 不得凭设计经验编造 DSH 控件、状态、布局、动效或图标。没有实际截图或源码依据的状态，标为暂缓并隐藏 HTML 演示。
4. 用 data/demo-evidence.json 记录每个演示的原始截图、网页裁图、场景和归属；在 docs/reference/demo-evidence.md 保持可读的对应表。
5. 公网页面只使用匿名裁图。遮挡会话正文、会话标题、工作区名称、凭据、用量和其他用户数据；原始截图仅用于用户审阅和本地复核。
6. 明确区分 DSH 产品元素、官方可复用实现、插件贡献内容和本仓库建议。插件占用 DSH 预留区域时，截图只能证明宿主位置，不得把插件卡片写成 DSH 自带控件。

## 需要解决的界面问题

- 左侧目录同一树中只能有一个当前项。打开分组不等于当前页；查看分类页时只高亮分类，查看子项时只高亮子项，查看全部页面时只高亮“全部”。
- 所有一级页面标题使用一致的字号、字重、行高和纵向起点；眉题占位规则统一，标题不能因是否显示分类眉题而上下跳动。
- 修复 token-scale 中 elevation-prominent 的卡片与文字居中、内边距和换行；长 box-shadow 读数不得把第四张卡挤到另一行。
- 按 DSH 窗口区域和作者任务组织界面元素，逐项说明外观、用途、交互、关键状态、键盘行为和可复用实现。可参考 Huawei 文档按控件分类和说明控件的结构，但不要照搬其平台尺寸、组件名称、品牌样式或设备交互。
- 外部指南只用于少量通用判断。DSH 自身的截图、官方 CSS、语义令牌、运行时数据和官方公开文档是本规范的主要依据；同一外部原则不要在多页重复抄写。

## 演示规则

- 页面先显示真实 DSH 截图，再显示清楚标注的 HTML 示意；内容列较窄时上下排列。
- 规则图、清单和冲突分析等说明工具必须标为“非产品界面”，并配上其讨论对象所在的真实 DSH 场景。
- 每个可见 HTML 示例都必须有 verified 实景记录和对应裁图。没有实景的组件状态标为 withheld，不得挂载示例。
- 组件徽标说明“产品中可见”或“本仓库建议”，不得把有产品视觉对应物误写成 DSH 官方导出的同名 API。
- 用中性示例数据，不复制真实会话正文、个人路径、凭据或统计数值。

## 核对要求

维护后在浏览器检查目录高亮、不同页面一级标题对齐、截图在示意之前、暂缓组件没有 HTML 示意，以及桌面和窄窗口布局。记录实际执行的构建或检查命令；不要把未运行的检查写成已通过。

交付时简要列出修改文件、实景证据覆盖情况、仍暂缓的状态及其所需截图。若实景与既有规范或组件实现冲突，先保留截图和事实，再将差异登记为已知偏差，不要为追求外部风格而覆盖 DSH 原生控件。
