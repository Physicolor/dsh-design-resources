# 双语语料契约（I18N）

这份文档管**面向读者的每一段文字怎么按语言放置**。`docs/LANGUAGE.md` 管"每一句人话怎么写"，
`docs/WRITING.md` 管"组件怎么分两份写"，这份文档管"同一段内容的中英两份放在哪里、怎么保证不过期"。

判据只有一条，任何改动都按它验收：

> **站点切到 EN 时，页面上不出现中文字符。** 唯一的例外是被显式标记为「产品实景文案」的引用串
> （见第五节）——那是证据，不是我们的文案。

## 一、语料分层

英文版要清干净，得先分清哪一层是"我们写的话"，哪一层是"机器产出的东西"。

| 层 | 语料 | 英文版从哪来 |
| --- | --- | --- |
| 正文 | `spec/*.md`、`guides/*.md`、`components/**/README.md`、`components/**/SPEC.md` | 语言对文件（第二节） |
| 清单散文 | `components/index.json` 的 `summary` / `whenToUse` / `whenNotToUse` / `geometrySource` / `tags` | 同文件 `*En` 键 |
| 证据说明 | `data/demo-evidence.json` 的 `scene` / `note` / `reason` | 同文件 `*En` 键 |
| 提案场景 | `components/origins.json` 的 `scenes` | 同文件 `scenesEn` |
| 示意页文案 | `website/demos/*.html`、`components/**/demo.html` 的可见文字 | 单文件 + `data-t` 键（第五节） |
| 产品标签释义 | 正文里引用的产品界面串（`通用设置` 等） | `data/product-labels.json` 的 `labels`（第六节最后一条） || 源码注释 | `*.tsx` / `*.module.css` / demo 的 `<!-- -->` 与 `/* */` | 直接写成英文，不做语言对 |
| 生成数据 | `data/ui-inventory.json`、`data/ui-coverage.json`、`data/inventory-anchors.json` | 生成器里写成英文；插件名用 `plugin` / `pluginEn` |
| 界面词典 | `language/zh.json`、`language/en.json` | 两份都手写 |
| 贡献者文档 | `docs/*.md`（不参与站点渲染） | 不翻译，保持中文 |

**判据只管"页面"。** 上表里只有会渲染到页面上字段才需要英文：`components/index.json` 的
`geometrySource` 与 `tags`、`data/demo-evidence.json` 的 `scene` 与 `reason`、
`inventory-anchors.json` 的 `pluginNamesEn`。数据文件里给维护者看的元字段
（`$comment`、`demo-evidence` 的 `note`、`origins.json` 的 `source` / `revision` / `scenes`、
`inventory-anchors.json` 的 `anchors[].note`）**不进站点**，因此不要求英文——逼它们各配一份译文
只会多出一份要同步的东西。`docs/reference/chrome.json` 与示意页里 `data-capture` 标记的串是
**产品实景复刻**，中文是忠实的，不是漏译。

## 二、正文的语言对

中文是**就地**的那一份，英文放同名的 `en` 兄弟路径。这样中文文件的路径不变，所有既有的
引用、`check-refs.mjs`、`rules/` 里的出处都不受影响。

| 中文 | 英文 |
| --- | --- |
| `spec/20-controls.md` | `spec/en/20-controls.md` |
| `guides/00-start.md` | `guides/en/00-start.md` |
| `components/controls/Button/README.md` | `components/controls/Button/README.en.md` |
| `components/controls/Button/SPEC.md` | `components/controls/Button/SPEC.en.md` |

英文那一份**必须有**下面这个 frontmatter，用来把译文钉在它翻译时读到的中文版本上：

```
---
source: spec/20-controls.md
source-sha256: 3f9a1c…
translated-at: 2026-10-05
---
```

`source-sha256` 是**中文源文件**（去掉它自己的 frontmatter 之后）的 sha256 前 16 位。
`website/gen-site.mjs` 渲染前会剥掉这个 frontmatter，`scripts/check-i18n.mjs` 会重算并比对。

> 中文改了、英文没跟上时 `check-i18n.mjs` 直接失败。这是这份契约存在的理由：
> 一份"曾经译过"的文档比没有译文更危险，读者会按过期的规则做。

## 三、导航与覆盖率

- **EN 导航里只出现有 `en` 兄弟文件的文档。** 没有译文的文档在 EN 模式下不进左栏、不进卡片、
  不进搜索——读者不会点进一个中文页面。
- ZH 导航永远显示全部文档，与今天的表现一致。
- EN 首页显示真实覆盖率（`data.i18nCoverage`），例如 `6 / 10 spec documents translated`。
  覆盖率是算出来的，不是写死的。
- `data.js` 里每篇文档的正文变成按语言分组的对象（`html: { zh, en }`），`title` / `summary` /
  `tasks` 同理。`website/js/app.js` 按当前语言取值，取不到就当作该文档没有这一语言。

## 四、`*En` 键的写法

同一文件里加平行的 `En` 键，不改原键。`gen-site.mjs` 在生成时按语言取，缺 `En` 键就
**报错**（清单类数据没有"缺一份也能跑"的选项——它出现在每一张卡片上）。

```json
{
  "id": "button",
  "summary": "一个 <button> 包装：四种视觉家族 + 两种尺寸 + 可选前置图标。",
  "summaryEn": "A <button> wrapper: four visual families, two sizes, an optional leading icon."
}
```

`；` 分隔的列表在两种语言里都是 `；` / `;` 分隔，条目数必须相等，`check-i18n.mjs` 会数。

## 五、示意页文案

示意页（demo）只有**一份** HTML。不做语言对的理由是几何与 CSS 完全共用，复制一份等于
把 11 000 行样式维护两遍。可见文字按来源分两类：

**1. 我们自己写的文案** —— 加 `data-t` 指到词典键，`app.js` 挂载 demo 时在 shadow root 里
替换文字：

```html
<p class="demo-label" data-t="demo.button.settingHeader">设置窗口页头 · 紧凑 outlined · 实景文案</p>
```

键**不写在** `language/zh.json` / `language/en.json` 里，而是每个示意页一份
`language/demos/<demoId>.json`：

```json
{
  "zh": { "settingHeader": "设置窗口页头 · 紧凑 outlined · 实景文案" },
  "en": { "settingHeader": "Settings window header · compact outlined · copy as captured" }
}
```

`<demoId>` 是 `website/demos/<id>.html` 的 `<id>`，或组件示意页的组件 id（`button`）。
`gen-site.mjs` 把每份表并到 `demo.<id>` 命名空间下，两份键必须完全一致，不一致直接构建失败。
一份文件一个示意页，是为了两个人在译两份示意页时不会写同一个文件。

直接用 `file://` 打开 demo 单页时看到的是源文件里的中文原文，这是预期的降级。

**2. 产品实景文案** —— 从运行中的产品截图里逐字抄下来的按钮标题之类。**它必须保持原样**，
因为 SPEC 的几何与文案是对着截图核的；改成英文会让"实景文案"这句话变成假的。这类串加
`data-capture` 标记：

```html
<button type="button" class="button outline sm" data-capture="设置窗口页头">打开配置文件</button>
```

`app.js` 给带 `data-capture` 的元素加 `lang="zh-CN"`，字体与读屏因此把它当引用；
`gen-site.mjs` 在示意页标题旁边加一句"含产品实景文案（原样保留）"。
**不在串旁边插任何节点**——示意的盒模型本身就是这一页在断言的东西。

源码注释（`<!-- -->`、`/* */`、`//`）没有语言变体：**一律写成英文**。

## 六、自检

```sh
node scripts/check-i18n.mjs            # 覆盖率 + 过期译文，失败即退出非零
node scripts/check-i18n.mjs --update   # 翻译完成后刷新 source-sha256（新文件也会补上 frontmatter）
node scripts/check-demos-i18n.mjs      # 示意页层：注释、data-t 键、data-capture、sidecar 键位
node website/gen-site.mjs              # 内联进 website/js/data.js
node website/verify.mjs                # EN 页面零中文、每条中文引用都有释义、覆盖率
npm run build                          # 上面全部串起来，缺一项就红
```

`scripts/check-i18n.mjs` 的判定，按顺序：

1. 每个 `spec/`、`guides/`、`components/**/README.md|SPEC.md` 的中文文件，是否有 `en` 兄弟文件；
2. 每个英文文件是否有合法 frontmatter，`source` 指向真实存在的中文文件；
3. `source-sha256` 是否等于中文源文件当前的哈希；
4. 每份 `*En` 键是否有对应的中文键，`；` 分隔的条目数是否相等；
5. 汇总覆盖率，写进 `data.js` 的 `i18nCoverage`。

`scripts/check-demos-i18n.mjs` 用一棵小型元素树走每个示意页，判定：

1. 每个有中文的文本节点，必须在带 `data-capture` 的祖先里，或在带 `data-t` 的元素里；
2. 每个有中文的属性，必须是 `data-capture` 或 `data-t` / `data-t-aria` / `data-t-title`；
3. `data-t` 不能落在有子元素的元素上（挂载时会吃掉子元素）；
4. sidecar 的 `zh` 与 `en` 键集合完全一致、`en` 值不含中文、没有孤立键。

`website/verify.mjs` 的浏览器前段另外判两条：

1. EN 文档里 `<code>` 之外没有中文字符（含全角标点）；
2. EN 文档里每一条中文引用（`<code>` 且不含 `<` `>` `=` 引号）后面都跟着
   `<span class="site-gloss">`——也就是都进了 `data/product-labels.json`。
   没进的引用会让构建红，而不是留在页面上让人猜。
