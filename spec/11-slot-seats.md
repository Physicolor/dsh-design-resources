# 11 座位目录与选择指南

- 适用对象：任何声明 slot 的插件。
- 效力：含 MF / RC / AD，逐条标注。
- 本文的判据是否可自动检测：多数可。座位 id 是否已声明、list 座位是否声明 order、order 是否撞车、是否占用 `replaceRisk: shadows-shipped-ui` 的座位，均可静态扫描；「是否真的需要这个座位」只能人工审查。

## 1. 座位模型

[实测] DSH 官方声明了约 64 个 UI 座位。座位有四种类型、三种作用域，并带 `replaceRisk` 标注。

| 类型 | 语义 | 多插件关系 |
| --- | --- | --- |
| `single` | 唯一占用 | 后占用者替换先占用者；占用即遮蔽官方 UI |
| `list` | 列表 | 多插件共存，按 order 升序排列 |
| `keyed` | 按 key 分发 | 按上层传入的 key 选择渲染目标 |
| `chain` | 选择器路由 | 可整段替换路由结果 |

| 作用域 | 渲染条件 |
| --- | --- |
| `root` | 全局，无会话也存在 |
| `session-maybe` | 无会话时也在，但内容与会话相关 |
| `session` | 必须选中会话才渲染 |

| replaceRisk | 含义 | 占用纪律 |
| --- | --- | --- |
| `none` | 安全新增 | 按本文第 2、3 节执行 |
| `shadows-shipped-ui` | 占用会遮蔽官方界面，高风险 | 追加第 4 节纪律 |

权威座位清单以 DSH 自身声明为准（随版本变化）；本规范不复制清单，只规定选择与占用方式。座位 id 必须来自该声明，不得自造。

## 2. 选择流程

按顺序执行，任一步得出座位即停止：

1. 同类内容是否已有官方座位承载？→ 复用该座位。禁止自造座位名（未声明座位不保证渲染）。`SL-MF-01`
2. 无会话时是否必须存在？是 → 作用域取 `root` 或 `session-maybe`；否 → 取 `session`，避免无会话时渲染空壳。`SL-MF-02`
3. 需要多插件共存 → `list`；需要在多个同类目标间分发 → `keyed`；需要接管一段路由 → `chain`；独占替换 → `single`（进第 4 节）。
4. 目标座位 `replaceRisk` 为 `shadows-shipped-ui` → 执行第 4 节纪律。
5. 座位为 `list` → 必须声明 order（第 3 节）。

## 3. list 座位的 order 规范

- `SL-MF-03`：[实测] `list` 座位必须显式声明 order，禁止依赖默认 0。证据：`shell.overlay` 14 个占用者中 13 个未声明 order，全部落在默认值 0，层级顺序由注册时序决定，不可预测；反例是 `conversation.session.header.utilities`，4 个占用者显式 -10 / -5 / 0 / 5，顺序可解释。
- `SL-RC-04`：order 建议分段。无权威数值，本仓库建议如下，理由：让「忘记声明」与「有意居中」可区分，并给后续插入留出空间。

| 区间 | 用途 |
| --- | --- |
| ≤ -10 | 预留：框架级、主流程前置项 |
| -9 .. -1 | 优先级前置 |
| 0 | 保留给官方既有占用；插件默认不取 0，除非与官方既有项做锚定 |
| 1 .. 99 | 常规新增，按 +10 递增 |
| ≥ 100 | 保留，阻止用户级插入 |

- `SL-MF-05`：新增到已有占用者的座位时，取该座位当前最大 order + 10。与现有值相撞视为缺陷（处置见 80-conflicts.md）。[本仓库建议]
- `SL-RC-06`：同一 bundle 在同一座位的多个 entry，相邻 order 间隔 ≥5。理由：[实测] 官方样板 `conversation.session.header.utilities` 的步长即为 5（-10 / -5 / 0 / 5）。间隔要求为本仓库建议。
- `SL-AD-07`：同一插件在同一座位不得注册超过 3 个 entry。超出说明该座位被当作菜单使用，应改用 `keyed` 或自带弹出层。[本仓库建议]

## 4. single 与 shadows-shipped-ui 占用纪律

- `SL-MF-08`：占用 `replaceRisk: shadows-shipped-ui` 的座位，必须在插件 manifest 或 README 显式声明「本插件遮蔽官方 X 界面」，并提供关闭开关，使用户可一键恢复官方界面。[本仓库建议]
- `SL-MF-09`：禁止遮蔽官方唯一入口：发送、停止、设置总入口、关闭。判定：该控件在官方 UI 中位于 `single` 座位且不存在替代路径。[本仓库建议]
- `SL-MF-10`：`single` 座位不接受 order 调停——order 对 single 无意义。被遮蔽方的处理走 80-conflicts.md 第 4 节申诉路径。

## 5. keyed 与 chain

- `SL-MF-11`：`keyed` 座位的 key 必须稳定（常量或稳定标识），禁止使用时间戳、随机数、会话内递增序号。key 变更属破坏性变更。[本仓库建议（官方未公开 key 稳定性要求）]
- `SL-MF-12`：`chain` 座位占用者在未匹配时必须回落到官方实现，不得吞掉未知输入。[本仓库建议]

## 6. 左栏底部入口

- `SL-MF-13`：`sidebar.footer.action` 中，一个按钮 = 一个 list entry。禁止 wrapper 包多个按钮（与 `FL-MF-09` 同一条纪律的座位侧表述）。[实测]
- `SL-RC-14`：该座位 order 按 `SL-RC-04` 的 1..99 区取 +10 递增；同一 bundle 在此座位通常只需要 1 个 entry（入口归并到插件自身面板）。[本仓库建议]

## 7. 自查

发布前确认：座位来自官方声明；作用域与会话依赖一致；list 座位有显式 order 且未撞车；占用 shadows-shipped-ui 座位时有声明与关闭开关。对应 70-checklist.md 的 SL 分组。
