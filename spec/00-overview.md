# 00 总览：DSH 设计规范层

- 适用对象：为 DeepSeek Harness（DSH）编写插件的社区作者、插件审核者、以及在同一界面内与他人共存的所有 UI 贡献者。
- 效力：本篇为元文档，规定其余各篇的效力标注、编号方式与数值来源标注要求；本篇自身不含强制条文。
- 本文的判据是否可自动检测：不适用（元文档）。本篇规定的「可检测性标注」由 70-checklist.md 落地执行。

## 1. 缺口是什么

DSH 官方为插件作者提供的兼容层覆盖技术栈：Cordis 插件系统、slot 座位声明、`--dsw-*` 设计 token。它回答「能挂在哪、能用什么变量、有哪些语义色」，不回答「该多大、该多远、该多快、重复占用时谁优先」。

后果有实据，不是假设：

| 座位 | 占用者 | 已核实事实 |
| --- | --- | --- |
| `shell.overlay` | 14 | 其中 13 个未声明 `order`，全部落在默认值 0，层级顺序由注册时序决定，不可预测 |
| `settings.section` | 11 | research-cordis / dsh-market / ui-harmony 三者 order 均为 40，顺序无法解释 |
| `conversation.session.header.utilities` | 4 | order 分别 -10 / -5 / 0 / 5，排布清晰，可解释 |

三个都是 `list` 座位，差别只在是否声明 order。这层空白就是本仓库要补的内容。

## 2. 效力层级

| 标记 | 名称 | 含义 | 违反时的处理 |
| --- | --- | --- | --- |
| MF | 强制 | 不满足即判为缺陷，审核可拒 | 必须修改或给出书面例外理由 |
| RC | 推荐 | 默认照做；偏离需在插件 README 说明理由 | 不阻塞合并，但记录在案 |
| AD | 建议 | 供取舍参考，允许按场景判断 | 无需说明 |

一篇文档可同时包含三种效力。任何条文的效力必须显式标注；未标注效力的句子不构成条文。

## 3. 规则编号与引用

编号格式：`<域>-<效力>-<序号>`，例 `FL-MF-03`（骨架域、强制、第 3 条）。域代码：FL 骨架、SL 座位、CT 控件、TK 令牌、MO 动效、IC 图标、AC 可访问性、CF 冲突。

70-checklist.md 只引用编号，不重复正文数值；数值以正文为准。引用方式：「依据 DSH Design Resources `FL-MF-03`」。

## 4. 数值来源标注（本仓库的根本约束）

任何数值必须携带来源标签：

| 标签 | 含义 |
| --- | --- |
| [HIG] | Apple Human Interface Guidelines 官方条文 |
| [OH] | OpenHarmony 官方文档全文 |
| [DSH-CSS] | DSH 官方未压缩 CSS 源（部分注释注明来自 Figma 组件实例） |
| [实测] | 在本仓库对本机 DSH 资产/声明做全量统计得出，方法可复现 |
| [本仓库建议] | 无权威数值，本仓库给出的建议值与理由 |

铁律：凡数值无来源标签，即为缺陷。凡某维度确实没有权威数值，必须写成「无权威数值，本仓库建议 X，理由 Y」，不得沉默、不得伪造出处。Apple HIG 没有公开的 8pt 栅格，也没有官方动效时长；本仓库不得声称它们存在。

## 5. 不做什么

- 不评判审美：不规定品牌色相、不规定插画风格、不评价「好看」。本规范只保证一致与可用。
- 不重复官方技术文档：座位声明语法、token 变量名以 DSH 官方为准；本规范只规定用法、组合与冲突处置。
- 不假装能强制：本规范是仓库产物，不是 DSH 运行时校验器。它让违规可被发现、可被指认，不能使违规无法发生（见 80-conflicts.md 第 5 节）。
