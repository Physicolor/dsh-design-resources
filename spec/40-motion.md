# 40 动效规范（参考档位，非官方要求）

- 适用对象：含过渡或动画的插件 UI。
- 效力：**全部为 RC（推荐）与 AD（建议），本文没有 MF（强制）条款。** 官方客户端没有公开任何时长与曲线数值，本仓库只是给出一组可以照抄的档位；判定见 [70 自检清单](70-checklist.md) 的 B13–B20。
- 本文的判据是否可自动检测：是（时长取值、曲线函数、是否存在 reduce 媒体查询、是否为布局属性动画，均可静态扫描）。

## 0. 来源说明（先读）

DSH 官方未公开动效时长与缓动曲线数值。Apple HIG 同样没有公开的动效时长表——任何声称「HIG 规定 200ms」的说法都是编造。因此本规范的动效数值唯一权威来源是 [OH]（OpenHarmony 官方文档全文）的五档时长与标准曲线。这与控件几何的来源（DSH 官方 CSS）不同，引用时应写明来源。

**官方到底有哪些动效**（[运行时实测]）：官方客户端公开的过渡集中在少数几处——工作区搜索框的展开与收起、左栏开合、右栏开合、会话头部的页签切换、浮层与菜单的出现消失；除此之外大量交互没有过渡。因此本规范是**参考档位**，不是对官方行为的复刻：照抄官方控件自带的过渡值优先（见 [总览 4.1](00-overview.md)），没有官方值可抄时再取下面的档位，且在 README 里说明这是本仓库建议。

## 1. 时长五档

[OH] 官方五档：100 / 150 / 200 / 300 / 350 ms。

| 时长 | 适用 |
| --- | --- |
| 100ms | 微反馈：按下、hover 变色、状态点切换 |
| 150ms | 小元素状态切换：Switch、Checkbox、Tag、Pill |
| 200ms | 常规过渡：展开/收起、淡入淡出、位移小于 100px |
| 300ms | 较大区域进入：面板、侧栏、浮层出现 |
| 350ms | 上限：全屏或大面板的进入 |

- `MO-RC-01`：过渡时长必须取 100 / 150 / 200 / 300 / 350 之一。禁止 250、400、500 等中间值；禁止超过 350ms。判定：`transition-duration` 与 `animation-duration` 的取值集合必须是上述五档的子集。
- `MO-RC-02`：同一次状态变化中，所有参与元素使用同一档时长。需要层次感时用不超过 100ms 的错峰延迟，不得改用不同时长。[本仓库建议]
- `MO-RC-03`：进入与退出时长必须对称。理由：无权威来源支持非对称；非对称会让取消操作显得迟滞。[本仓库建议]

[已知偏差] 本仓库组件实现里有两处过渡值落在这五档之外，引用组件源码时不要把它们当范例：`components/controls/Switch/switch.module.css` 第 21 行 `--dsh-switch-duration: 120ms`（这类小元素状态切换的档位是 150ms），`components/feedback/InlineNotice/inline-notice.module.css` 第 38 行 `160ms ease-out`（既不在五档内，也不是标准曲线）。本轮登记而不改实现，避免在不相关的改动里动既有视觉行为；新增过渡的时长仍须落在 `MO-RC-01` 的五档内、曲线仍须取 `MO-RC-04` 的标准曲线，这两处遗留值不构成先例。[本仓库建议]

## 2. 缓动曲线

- `MO-RC-04`：标准曲线为 `cubic-bezier(0.40, 0, 0.20, 1)`，用于绝大多数位移与尺寸变化。[OH]
- `MO-RC-05`：线性曲线（`linear`）只允许用于持续进度（进度条、骨架屏的位移），不得用于交互反馈。[本仓库建议]
- `MO-RC-06`：禁止使用 `ease` / `ease-in-out` 等未与官方曲线对齐的默认值作为交互过渡曲线。判定：扫描 `transition-timing-function`，只允许标准曲线、`linear`（限进度）与 `steps()`（限离散帧）。[本仓库建议]

## 3. 动什么、不动什么

| 应当有动效 | 不应有动效 |
| --- | --- |
| 状态变化（hover、选中、禁用） | 首屏入场表演（逐块飞入、延迟显示） |
| 出现与消失（浮层、菜单、面板） | 循环装饰动画（呼吸、缓慢旋转的装饰图形） |
| 位置变化（列表项移动、拖拽落位） | 文字逐字打字（除流式生成内容的原生行为） |
| 进度与加载 | hover 时改变尺寸导致布局重排 |
| 展开与收起 | 对数值变化做纯装饰性滚动 |

- `MO-RC-07`：禁止无限循环动画，除非它表达正在进行的进程（loading、生成中）。其余循环动画判违规。
- `MO-RC-08`：禁止对触发布局的属性做动画（width、height、top、left、margin、padding）。应使用 `transform` 与 `opacity`。理由：[OH] 要求交互类动画强制 60FPS；只有 `transform` / `opacity` 能在不触发布局重排的前提下稳定达成。判定：扫描 transition 属性列表。

## 3.1 进行中的动效（加载 / 运行态）

持续动效不属于时长五档——`MO-RC-01` 管的是状态过渡（点一下、开一下），这里管的是「一直在跑」。官方为此有三套并存的实现，周期都是 1s 或 1.5s：

| 形态 | 周期与曲线 | 出处 |
| --- | --- | --- |
| 运行圆环（转 + 弧伸缩） | 转 `1.5s linear infinite`；伸缩 `1.5s ease-in-out infinite` | 客户端 CSS 模块 `_spinnerMotion_1i3xo_42` / `_spinnerArc_1i3xo_48`；组件见 `components/feedback/RunningRing/` |
| 像素追逐（库里 `StateDot` 的 `ongoing`） | `1s` 无限，四段离散台阶（`opacity` 1 / 0.6 / 0.35 / 0.15），逐格 `animation-delay` 相差 125ms | `@deepseek-ai/dsh-client-ui-primitives/lib/StateDot.module.css` `@keyframes dsh-state-dot-chase` |
| 三点依次出现 | `1.5s` 无限，`step-end` | `ConnectionIndicator.module.css` `.secondDot` / `.thirdDot` |
| 运行提示行的鲸鱼动画 | 字形 **14 × 14**，随「深度求索中，用时 …」一行 | 采集：左栏会话行与输入区上方的运行提示 |

- `MO-RC-12`：持续进行中的动效周期只能取 `1s` 或 `1.5s`，且必须是 `infinite`。判定：扫描 `animation-iteration-count: infinite` 的 `animation-duration`。
- `MO-RC-13`：同一条「正在进行」的信息，一个界面里只用一种形态。会话行首用了运行圆环，就不要在同一行再挂三点或追逐方块——它们是三套官方实现，不是三个粒度。
- `MO-RC-14`：能用确定式进度（知道还剩多少）就不要用转圈。这是 Apple HIG 的取向（[Progress indicators](https://developer.apple.com/cn/design/human-interface-guidelines/progress-indicators)：能确定时长时优先 determinate，因为它能帮用户决定要不要先去做别的）。官方目前没有进度条组件，插件要用就自己实现，但**别把转圈当作「反正差不多」的替代**。

**官方自身的不统一（按 HIG 判定）**：官方 primitives 包给 `ongoing` 的是像素追逐矩阵，而产品实际渲染在会话行首的是转圈环——两套并存，库里那套在真实界面里没有出现。HIG 把「时长不可估」的等待归为 indeterminate，其形态就是 spinner（「All platforms support a circular image that appears to spin」），并且建议在空间受限的小区域优先用 spinner。**判定：这是官方没统一，不是有意的设计分工；跟产品走（转圈环），追逐矩阵只在必须用库里 `StateDot` 时才会出现。**（活的对照在 `components/feedback/RunningRing/` 的预览里。）

## 4. prefers-reduced-motion（强制）

- `MO-RC-09`：必须响应 `prefers-reduced-motion: reduce`。在该模式下，所有非必要的位移、缩放、旋转改为即时（0ms）；允许保留透明度变化与加载指示器，但加载指示器不得有大幅位移。
- `MO-RC-10`：必须使用 CSS 媒体查询或在运行时监听 `matchMedia` 变化；禁止在启动时读一次结果后写死（用户在系统设置中切换后应立即生效）。[本仓库建议]
- 判定：样式表中不含 `prefers-reduced-motion` 即判违规（可自动检测）。

## 5. 性能预算

- `MO-RC-11`：交互类动画全程 60FPS。[OH] 由 60FPS 定义推出：单帧预算约 16.7ms。
- `MO-RC-12`：同一屏幕内同时运行的动画不超过 2 组。无权威数值，本仓库建议 2，理由：并发动画是丢帧的主要来源，且并发动画在视觉上互相争夺注意力。[本仓库建议]
- `MO-RC-13`：首屏不得有动画。理由：首屏动画推迟可交互时间，而首屏本就没有状态变化可表达。[本仓库建议]
- `MO-AD-14`：长列表滚动区域内的元素不做出现动画（虚拟滚动会反复触发）。[本仓库建议]

## 6. 可检测与不可检测

- 可自动检测：时长取值是否落在五档内、是否超过 350ms、曲线是否为标准曲线、是否存在无限循环动画、是否有 `prefers-reduced-motion` 分支、是否动画了布局属性。
- 不可自动检测：动效是否「恰当」（该不该有、节奏是否自然），需人工审查。
