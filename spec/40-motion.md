# 40 动效规范

- 适用对象：含过渡或动画的插件 UI。
- 效力：含 MF / RC / AD，逐条标注。
- 本文的判据是否可自动检测：是（时长取值、曲线函数、是否存在 reduce 媒体查询、是否为布局属性动画，均可静态扫描）。

## 0. 来源说明（先读）

DSH 官方未公开动效时长与缓动曲线数值。Apple HIG 同样没有公开的动效时长表——任何声称「HIG 规定 200ms」的说法都是编造。因此本规范的动效数值唯一权威来源是 [OH]（OpenHarmony 官方文档全文）的五档时长与标准曲线。这与控件几何的来源（DSH 官方 CSS）不同，引用时应写明来源。

## 1. 时长五档

[OH] 官方五档：100 / 150 / 200 / 300 / 350 ms。

| 时长 | 适用 |
| --- | --- |
| 100ms | 微反馈：按下、hover 变色、状态点切换 |
| 150ms | 小元素状态切换：Switch、Checkbox、Tag、Pill |
| 200ms | 常规过渡：展开/收起、淡入淡出、位移小于 100px |
| 300ms | 较大区域进入：面板、侧栏、浮层出现 |
| 350ms | 上限：全屏或大面板的进入 |

- `MO-MF-01`：过渡时长必须取 100 / 150 / 200 / 300 / 350 之一。禁止 250、400、500 等中间值；禁止超过 350ms。判定：`transition-duration` 与 `animation-duration` 的取值集合必须是上述五档的子集。
- `MO-MF-02`：同一次状态变化中，所有参与元素使用同一档时长。需要层次感时用不超过 100ms 的错峰延迟，不得改用不同时长。[本仓库建议]
- `MO-RC-03`：进入与退出时长必须对称。理由：无权威来源支持非对称；非对称会让取消操作显得迟滞。[本仓库建议]

## 2. 缓动曲线

- `MO-MF-04`：标准曲线为 `cubic-bezier(0.40, 0, 0.20, 1)`，用于绝大多数位移与尺寸变化。[OH]
- `MO-MF-05`：线性曲线（`linear`）只允许用于持续进度（进度条、骨架屏的位移），不得用于交互反馈。[本仓库建议]
- `MO-MF-06`：禁止使用 `ease` / `ease-in-out` 等未与官方曲线对齐的默认值作为交互过渡曲线。判定：扫描 `transition-timing-function`，只允许标准曲线、`linear`（限进度）与 `steps()`（限离散帧）。[本仓库建议]

## 3. 动什么、不动什么

| 应当有动效 | 不应有动效 |
| --- | --- |
| 状态变化（hover、选中、禁用） | 首屏入场表演（逐块飞入、延迟显示） |
| 出现与消失（浮层、菜单、面板） | 循环装饰动画（呼吸、缓慢旋转的装饰图形） |
| 位置变化（列表项移动、拖拽落位） | 文字逐字打字（除流式生成内容的原生行为） |
| 进度与加载 | hover 时改变尺寸导致布局重排 |
| 展开与收起 | 对数值变化做纯装饰性滚动 |

- `MO-MF-07`：禁止无限循环动画，除非它表达正在进行的进程（loading、生成中）。其余循环动画判违规。
- `MO-MF-08`：禁止对触发布局的属性做动画（width、height、top、left、margin、padding）。应使用 `transform` 与 `opacity`。理由：[OH] 要求交互类动画强制 60FPS；只有 `transform` / `opacity` 能在不触发布局重排的前提下稳定达成。判定：扫描 transition 属性列表。

## 4. prefers-reduced-motion（强制）

- `MO-MF-09`：必须响应 `prefers-reduced-motion: reduce`。在该模式下，所有非必要的位移、缩放、旋转改为即时（0ms）；允许保留透明度变化与加载指示器，但加载指示器不得有大幅位移。
- `MO-MF-10`：必须使用 CSS 媒体查询或在运行时监听 `matchMedia` 变化；禁止在启动时读一次结果后写死（用户在系统设置中切换后应立即生效）。[本仓库建议]
- 判定：样式表中不含 `prefers-reduced-motion` 即判违规（可自动检测）。

## 5. 性能预算

- `MO-MF-11`：交互类动画全程 60FPS。[OH] 由 60FPS 定义推出：单帧预算约 16.7ms。
- `MO-RC-12`：同一屏幕内同时运行的动画不超过 2 组。无权威数值，本仓库建议 2，理由：并发动画是丢帧的主要来源，且并发动画在视觉上互相争夺注意力。[本仓库建议]
- `MO-RC-13`：首屏不得有动画。理由：首屏动画推迟可交互时间，而首屏本就没有状态变化可表达。[本仓库建议]
- `MO-AD-14`：长列表滚动区域内的元素不做出现动画（虚拟滚动会反复触发）。[本仓库建议]

## 6. 可检测与不可检测

- 可自动检测：时长取值是否落在五档内、是否超过 350ms、曲线是否为标准曲线、是否存在无限循环动画、是否有 `prefers-reduced-motion` 分支、是否动画了布局属性。
- 不可自动检测：动效是否「恰当」（该不该有、节奏是否自然），需人工审查。
