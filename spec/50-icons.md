# 50 图标规范

- 适用对象：在插件 UI 中使用图标，或需要自绘 SVG 的作者。
- 效力：含 MF / RC / AD，逐条标注。
- 本文的判据是否可自动检测：多数可（尺寸、viewBox、命名、fill/stroke 属性、内联色值均可静态扫描）；「视觉重量是否一致」「光学居中是否到位」需人工审查，但可按本文给出可复核口径。

## 1. 官方图标集事实

[实测] 对本机 DSH 官方图标资产做全量统计（方法可复现）：

| 项目 | 事实 |
| --- | --- |
| 图标总数 | 75 |
| 实现方式 | 全部为填充路径：`fill="currentColor"`，75/75 无任何 `stroke=` 属性 |
| 尺寸族 | 16×16 共 53 个；14×14 共 19 个；8×14 共 1 个；8.5×10.5 共 1 个；20×20 共 1 个 |
| 授权名 | `ic_ds_<name>_<style>_<size>`，例 `ic_ds_close_outline_16` |
| 组件名 | `Icon<Name><Style><Size>`，例 `IconCloseOutline16` |
| 文件名 | `<name>-<style>-<size>.svg`，例 `close-outline-16.svg` |

注意：名字中的 `outline` 指视觉风格，不是 SVG 实现方式——官方图标的实现一律是填充路径。因此「官方图标描边 1.5」这类说法不适用于 DSH 资产。

- `IC-MF-01`：复用官方图标时必须使用官方尺寸族（16×16、14×14、8×14、8.5×10.5、20×20）。禁止把 16 族 SVG 渲染成 12 或 18 等族外尺寸；需要更小时改用 14 族或 8×14 / 8.5×10.5 结构图标。判定：渲染尺寸 ∈ 上述族集合。

## 2. 尺寸选择

| 尺寸 | 用途 |
| --- | --- |
| 16×16 | 默认：按钮内（[DSH-CSS] 官方按钮图标容器 16×16）、工具行、列表行 |
| 14×14 | 紧凑行、Button `.sm`（h28）、密集列表 |
| 8×14 / 8.5×10.5 | 结构装饰（树形连接线等），不承载交互 |
| 20×20 | 个别大尺寸图标，按官方用途使用 |

- `IC-MF-02`：同一行、同一工具栏内的图标尺寸必须一致。判定：同一容器的图标渲染尺寸集合大小必须为 1。
- `IC-RC-03`：图标尺寸与相邻文字字号成对：16 图标配 14 号正文，14 图标配 12 号文字。[本仓库建议]，与 [HIG]「图标与相邻文字字重一致」的要求同源。

## 3. 自绘图标判据

- `IC-MF-04`：自绘图标必须与同族官方图标视觉重量一致。可复核口径：在同一 viewBox 下，比较「形状填充面积／外接框面积」比值与同族官方图标样本的偏差。无权威数值（DSH 未公开视觉重量阈值），本仓库建议偏差 ≤25%，理由：为人工目检提供可复算的口径，避免「看着差不多」这类不可判定表述。
- `IC-MF-05`：自绘图标的视觉描边宽度。官方未将描边宽度 token 化。实测样本（仅统计路径全部为直线段的图标，n=10）：16 族视觉描边中位数 1.301（样本 6），14 族区间 1.181–1.427（样本 3）；12 族仅 1 个样本（测得 3.508），样本量与数值均不足以推断，不采用。据此建议：16 族自绘描边取 1.25–1.5，14 族取 1.1–1.3。无权威数值，本仓库建议值，理由：与官方实测中位数对齐。测量方法：解析路径中的平行线段对，取最小垂直间距；曲线路径不参与统计。
- `IC-MF-06`：禁止混用不同风格图标：同一容器内不得同时出现填充式线性图标、多色插画图标与第三方风格图标。判定：同一容器内图标来源集合必须有唯一主来源。判定为自动（可按资产来源标记）加人工（视觉风格）。
- `IC-MF-07`：禁止用 emoji 作为界面语义图标（按钮、状态、列表前缀）。[本仓库建议]
- `IC-MF-08`：图标必须使用 `currentColor`，不得内嵌固定色值（**界面语义图标**；应用图标是另一层，见 §6）。判定（自动）：SVG 内出现 `fill="#`、`stroke="#` 或具名色即违规。理由：与 30-tokens.md 的主题要求一致。

## 4. 光学居中

- `IC-MF-09`：不对称图标（三角形、箭头、播放、对勾）必须在容器内做光学居中，而不是几何居中。[HIG]
- 可复核口径：先看外接框中心与容器中心的偏差；对重心明显偏移的图形允许补偿位移。无权威数值（补偿量），本仓库建议：16 族补偿不超过 1px，且必须使任一轴的视觉偏差小于几何偏差（即补偿后更居中，不能更偏）。
- `IC-MF-10`：图标在按钮内必须与文字基线视觉对齐；[DSH-CSS] 官方按钮为 `gap 4px` 的横向排列，禁止用额外 margin 伪造间距。

## 5. 命名

- `IC-MF-11`：自绘图标必须按 DSH 三段式命名（授权名 / 组件名 / 文件名三处一致）。[实测]
- [OH] 的六段命名 `ic_<模块>_<功能>_<位置>_<颜色>_<状态>_<数字>` 与 DSH 命名同构，映射如下：

| OpenHarmony 字段 | DSH 对应 |
| --- | --- |
| 模块 | name 的前缀（如 close、panel-left） |
| 功能 | name 主体 |
| 位置 | 由组件使用位置承担，不进入图标名 |
| 颜色 | 由 `currentColor` 与 token 承担，不进入图标名 |
| 状态 | style 字段（outline / fill） |
| 数字 | size 字段（16 / 14 / 8 等） |

- `IC-MF-12`：自绘图标不得嵌入颜色、不得嵌入尺寸（即不得写死 width/height，应由组件传入），否则无法适配 14 / 16 族与主题切换。

## 6. 应用图标（插件列表里那一层）

前五节讲的是**界面语义图标**：单色、走 `currentColor`、按 16 / 14 族选尺寸。产品里还有另一层图标——插件列表每行左侧那块彩色图标，它是插件的**身份标识**，规则完全不同。

<!-- demo: app-icon-board | 真实插件图标 + 实测行几何：容器 50 × 50 圆角 16、本体 36 × 36（四周各 7px）。下面三个量板按图标文件的真实路径现算「文件画布 / 墨迹外接框 / 外接圆」，可一键关掉标注对照原图。 -->

采集自 `docs/reference/plugin-row.json`（插件页一行，1570 × 905 视口）：

| 部位 | 实测值 |
| --- | --- |
| 行卡片 | 976 × 66 · 圆角 20（`padding 8px` / `gap 14px` 在行内的内容容器上，行本体 padding 为 0） |
| 图标容器 | **50 × 50 · 圆角 16** · 1px `rgba(0,0,0,.12)` 描边 · 底色透明（颜色由图标自己带） |
| 图标本体 | **36 × 36**，在容器里居中 → 四周各留 **7px** |
| 图标来源 | 插件自己的 `icon.svg`，产品内联成 `data:image/svg+xml;base64` 渲染（不是图标集的字形） |
| 标题 | **14 / 20 · 500** |
| 说明 | **13 / 18 · 400** |

- `IC-MF-13`：应用图标必须画在 **50 × 50、圆角 16** 的容器里，图标本体 **36 × 36** 居中；不得把图形铺满容器。
- `IC-MF-14`：**应用图标允许、也应当是多色的**——它是身份标识，不是界面语义。`IC-MF-08`（图标必须走 `currentColor`）只约束界面语义图标；把应用图标也做成单色，插件之间就只剩形状差别，列表里一眼分不出谁是谁。
- `IC-MF-15`：同一条列表里所有应用图标共用同一个容器尺寸与圆角，图形本体的视觉重量允许不同——容器统一，图标才不会被看出是两套东西。
- `IC-RC-18`：应用图标应出**浅色、深色两版**，而不是让同一个文件去猜底色。实测依据：产品自己的前端图标就是这么做的——`favicon.svg` 与 `favicon-dark.svg` 两个文件，用 `media="(prefers-color-scheme: dark)"` 选一个（见本机 `app.asar` 内 `dsh-web-frontend/dist/index.html`）。深色版不是把浅色版反色：本机 `dsh-widgets` 的两版里，右下角方块浅色版 `#5B9BF5`、深色版 `#7CB7FF`，底板由 `#FFFFFF` 换成 `#0B0C0E`。

**留白不是空间利用率不足**。[实测] 容器到本体那 7px 由产品给出（50 − 36 = 14，两侧各 7）；本体到图形外缘还有一圈是图标文件自己的内缩——演示里两个 36 × 36 的插件图标，墨迹实际只有 20 × 20 上下（浏览器按真实路径现测）。两段留白叠起来，图形距容器边缘约 15px。

产品为什么这么留，DSH 没有写；能引的是同一条道理在 Apple 的 App 图标指南里的表述：内容要居中，「避免系统调整圆角或施加遮罩时被截断」[^1]；背景保持简单，「不必把整块画布填满」[^1]。**本条只把它记为「同源」，不声称 DSH 是有意照它设计的**——仓库里只有几何证据：图形若顶到边上，圆角一裁就会啃掉内容的角，这一点与平台无关。

对照两层的分工（这也是 DSH 自身没有写清、由本节补齐的地方）：

| | 界面语义图标 | 应用图标 |
| --- | --- | --- |
| 颜色 | 必须 `currentColor`，随主题 | 多色，插件自己的品牌色 |
| 尺寸 | 16 / 14 族，按相邻文字选 | 固定 36 × 36，装在 50 × 50 容器里 |
| 形状 | 图形自己画，光学居中 | 容器提供圆角 16，图形不得贴边 |
| 出处 | `data/icons.json`（产品图标集） | 各插件自己的 `icon.svg` |
| 用在哪 | 按钮、行首、状态、导航 | 插件列表、插件详情、市场 |

## 7. 产品内联字形（不在图标集里的那些）

官方图标集是 75 个**文件**（§1），但产品界面里还有一批直接内联在组件里的字形：左栏导航、顶栏工具、输入区那一排。它们没有独立文件、没有授权名，插件作者只能从界面上看。元素清单按「viewBox + 第一条路径指纹」把它们认出来，共 **59 枚**（同一枚在多处出现会合并计数）。

| 字形 | 路径指纹（开头） | 渲染尺寸 | 用在哪 |
| --- | --- | --- | --- |
| 搜索 | `M6.58727 11.8586…` | 14 × 14 | 左栏搜索 |
| 新会话 | `M2.37091 11.2501…` | 14 × 14 | 左栏新会话按钮 |
| 插件 | `M7.84457 5.06199…` | 16 × 16 | 左栏面板导航 |
| 自动化任务 | `M8 14C11.3137 14…` | 16 × 16 | 左栏面板导航 |
| 用量中心 | `M12.0997 8.54554…` | 16 × 16 | 左栏底部入口 |
| 设置 | `M8 9.75012C8.9665…` | 16 × 16 | 左栏底部设置 |
| 添加工作区 | `M5.54492 2.06738…` | 16 × 16 | 左栏工作区标题行 |
| 智能体团队 | `M6 8.25C7.51878…` | 14 × 14 | 会话头部 chip |
| 折叠角 | `M4 6L7.29289 9.29289…` | 10 × 10 | chip 与菜单 |

- `IC-MF-16`：**不要照抄内联字形**。它们没有授权名、没有多尺寸族，也没有像图标集那样统一过内缩与描边；要一个「搜索」「设置」这样的字形，去 §1 的 75 个文件里找同义的，或按 §3 / §4 自绘。
- `IC-MF-17`：内联字形里那几个 10 × 10 / 15 × 15 / 12 × 16（折叠角、省略号、箭头）属于 `IC-MF-01` 的例外——**它们是随字号缩放的字形，不是独立图标**；插件自绘图标时仍按 16 / 14 / 8×14 / 8.5×10.5 / 20 这五个族取值。
