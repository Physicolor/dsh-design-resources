# 00 开始这里

> 这份资源把 DSH 官方分散的依据、本机实测的几何、以及可迁移的外部设计原则，整理成插件作者能直接用的判断与规格。先看这一页，再决定读哪一篇。

## 任务

- 搞清楚这份资源是什么、不是什么，以及它凭什么可信
- 按你手上的任务找到该读的那一篇
- 知道五种来源标记各代表什么，遇到没有标记的数字该怎么处理
- 知道怎么在本机复现这些结论

## 这份资源是什么

它是 **DeepSeek Harness 插件作者的设计参考**，由三部分构成：

| 层 | 内容 | 谁写的 |
| --- | --- | --- |
| 官方依据 | 官方公开仓库里的规则、令牌、组件实现（附文件路径） | 官方 |
| 运行时实测 | 在本机运行中的 Harness 上采集的几何、像素、占用者快照 | 本仓库脚本 |
| 本仓库建议 | 官方没有明文的地方给出的取值与理由 | 本仓库 |

三层刻意分开。**不要把第三层当成第一层**：本仓库建议是有理由的取值，不是官方承诺；官方一改，它就该跟着改。

## 不是什么

- **不是产品设计规范本身**。官方没有发布面向第三方插件作者的完整设计手册（这一点已在官方公开仓库的文档目录里核对过，见 `guides/01-official-basis.md`），本仓库补的是这段空白，而不是替官方立规。
- **不是视觉皮肤**。不套 Apple 或 HarmonyOS 的外观，不搬它们的平台数值（pt / vp / 系统组件名）。
- **不是全部**。只覆盖 DSH 界面上真实存在、且插件作者会遇到的东西：座位、控件、令牌、图标、动效、可访问性、设置页与面板等模式。

## 五种来源标记

正文里每个数字后面都会出现其中一种。没有标记的数值，按本仓库的铁律**视为缺陷**：

| 标记 | 含义 |
| --- | --- |
| `[官方源码]` | 官方仓库里的规则、令牌或组件实现，附文件路径或 URL |
| `[运行时实测]` | 在本机运行中的 Harness 上采集，方法可复现（附快照或脚本） |
| `[外部指南借鉴]` | Apple / 华为官方设计指南里可迁移的判断方式；只借原则，不搬平台数值 |
| `[本仓库建议]` | 官方没有明文，本仓库给的取值与理由 |
| `[已知偏差]` | 官方界面自身互相矛盾、或与官方规则不符之处：记录在案，不当最佳实践 |

## 三条硬约定

1. **座位优先**：先决定你的界面属于哪个座位，再决定它长什么样。位置选错，后面都白搭（看 `30`）。
2. **只用语义令牌**：颜色、圆角、字号、动效时长都走 `--dsw-*` / `--dsh-*`，不写字面值（看基础规范里的令牌与控件两篇）。
3. **先复用再新建**：官方已有的控件、容器、交互先看能不能扩展；新建的每一件都要能被验证（看 `10` 的检查标准与 `40` 的自检清单）。

## 怎么复现这里的结论

```bash
npm run build     # 结构 + 数据 + 浏览器渲染三层检查
npm run audit     # 真实浏览器里逐页点开每个演示的每个控件
npm run scan      # 重新扫描运行中的产品，刷新元素清单
npm run capture   # 重新采集产品截图与几何（写入 docs/reference/）
```

采集口径、已知缺口、以及「旧结论被推翻」的记录都在 `40 自检与来源` 与 `docs/`。本机运行版本与采集时间见首页右栏。
