# 官方没有座位的位置

> 认清四处官方没有给座位的地方，知道怎么借道、必须在 README 里声明什么、以及和同样借道的插件怎么共存。

## 读完这一页要能做什么

- 说出官方没有给座位的四处位置，并判断自己的内容是不是落在其中一处。
- 用借道方式把界面放上去，同时写清「官方无此座位」与降级行为。
- 躲开三种最常见的借道事故：动 body 级层级、越界盖住邻居、窗口变窄时不退场。
- 知道社区为此形成的约定在哪里，以及它现在还不是官方标准。

## 先认清：四处没有座位的位置

位置清单出自 [区域地图](../spec/05-region-map.md) 第 5 节。这里只补一句「为什么它没有座位」。

| 位置 | 官方座位 | 为什么没有 | 别人怎么用 |
| --- | --- | --- | --- |
| 中栏正文左右两侧的留白带 | 无 | 正文是固定宽度居中的，中栏比它宽出来的部分是**居中的副产物**，不是一个座位 | 借 `conversation.input.overlay` 这类浮动座位，再用绝对定位挪过去 |
| `conversation.input.overlay` 本身 | 有，但用途是「输入卡内部的浮动条目」 | 官方从没把它定义成中栏面板 | 被当作中栏右侧会话面板使用 |
| 独立插件设置窗口入口 | 无 | 官方只提供「通用设置里的一行偏好」和「设置里的一页」两种粒度 | 用 `settings.section` 落进宿主设置窗口 |
| 全局顶栏 / 窗口级命令栏 | 无 | 窗口是三条各自全高的轨道，没有横跨的栏 | 无处可放；不要用 `shell.overlay` 拼一条出来 |

有一件事值得先说清楚，因为它决定了你的做法：**第三方插件开不了新座位。** 官方客户端包的规矩是「渲染一个你没有声明的 slot，或者声明一个别人已经声明的 slot，都会在加载期失败」。所以「给留白带申请一个座位」这条路不存在，能走的只有借道。

## 借道怎么写

四步，缺一步就会在别人的环境里出问题。

**第一步：挑一个说得过去的座位。** 条件是三条同时满足——它是 `list`（能多家共存）、`replaceRisk` 是 `none`（不替换官方界面）、它的官方用途原文经得起你的用法。第三条最容易被跳过：`conversation.input.overlay` 的原文是「渲染在常驻输入卡内部的浮动条目」，所以借它的时候，你的东西**至少得还是一个浮动条目**；把一整块带边框、带标题、带图标的常驻面板说成「浮动条目」，是在拿座位名糊弄审查。

**第二步：在 README 里写明。** 一句话，两个信息：官方没有这个座位，以及你借的是哪一个。缺这句话，下一个人会以为这里是官方区域。

**第三步：定层级，但先找登记口。** 这是出事故最多的一步，见下一节。

**第四步：定降级。** 借道的座位随时可能被官方改动，你必须写清楚改动之后会发生什么。

- `RG-MF-20`：借道实现必须在 README 写明「官方无此座位，本插件借道 X 实现」，并给出降级行为；缺失即判为缺陷（`RG-MF-08` 在指南侧的展开）。[本仓库建议]
- `RG-MF-21`：借道的座位必须同时满足 `list`、`replaceRisk: none`、且官方用途原文与你的用法一致三条；只满足前两条不算通过。[本仓库建议]

## 层级：别自己定，先看有没有登记口

**这几种事故都是真的，而且都不会报错：**

- 公开仓库 `MeteorNOX/DeepSeek-Balance-Whale-Widget` 的层级审计工具记录过两次静默事故：一次是它的层级候选表引用了一个并不存在的标记，于是整条层级链一调用就抛，而这个异常被一个空的 `catch` 吞掉，界面上看不出任何异常；另一次是第三方新增了一个挂在 `body` 上的浮层，没有登记进候选表，结果两个窗口互相覆盖，双方都不报错。它给出的互操作答案是暴露一个私有全局函数让别的插件登记自己的遮罩。[官方源码]

这就是「你在别人的机器上盖住了别人的窗口，而控制台是干净的」这件事的完整形状。它不会在开发机上出现，因为开发机上往往只装了你一个插件。

**所以：**

- `RG-MF-22`：不要用 `body` 级、`documentElement` 级或极大 `z-index` 去争夺层级。先查当前环境有没有公开的层级登记口（官方没有；社区有插件各自维护的版本）。找不到登记口时，把你的浮层限制在借来座位的定位上下文里，不要往上爬。[本仓库建议]
- `RG-MF-23`：新增浮起表面按官方规则来：`border: 0` 配 `--dsw-elevation-*`，不要再叠一层边框或自造阴影。[官方源码]

### 社区约定在哪里

中栏留白带这块已经有维护中的社区约定，由 `dsh-ui-harmonizer` 维护，它把「占宽」和「层级」拆成两条独立的登记轴，并规定了合规清单与零改动兼容矩阵。**它不是官方标准**，是一份社区约定；用之前读它的当前版本，而不是照抄某个插件的实现。

- `RG-RC-24`：要在这条留白带上常驻的插件，建议按公开的中栏留白带约定登记占宽与层级，而不是各家自造一套；这会让你和已经在那里的插件（例如统计轨、余额挂件）一次就共存好。[本仓库建议]

## 零宽度：留白带会先消失

留白带的宽度是正文居中之后的余数，可以缩到 0，而借来的座位不会跟着消失。所以窗口变窄时，你的浮层会开始越界或者重新定位。

- `RG-MF-25`：借道留白带的内容必须有一个明确的零宽度行为，三选一：折叠成一枚按钮、收进输入卡内的 dock、或者整体隐藏。**不允许压到正文上。** 判定方法是把窗口收到正文达到最小宽度的程度，看你的界面是退场还是叠上去。[本仓库建议]
- `RG-MF-26`：借道的浮层不得在输入卡不可见时仍然占用交互区域；输入卡退场，浮层跟着退场。[本仓库建议]

## 和别的借道插件共存

同一片留白带上会有多家固定层。它们之间没有任何官方的排序依据，因为这里根本没有座位表。

- `RG-RC-27`：同一片留白带上多家共存时，先到者保留自己的位置，后到者收敛——折叠、缩窄或并进已有卡片，不要要求先到者让位。[本仓库建议]
- `RG-RC-28`：不要用「两边都放一份」（留白带一份、右栏再来一份）来规避「该放哪儿」这个决定。用户会看到同一份信息出现两次。[本仓库建议]

## 自检表

| 是 / 否 | 判定项 | 条文 |
| --- | --- | --- |
|  | README 写明了「官方无此座位」与借道的座位名 | `RG-MF-20` |
|  | 借的座位是 list、`replaceRisk` 为 none、且用途原文说得过去 | `RG-MF-21` |
|  | 没有用 body 级或极大 z-index 争夺层级 | `RG-MF-22` |
|  | 浮起表面用 `border: 0` + 官方高程，没有自造阴影 | `RG-MF-23` |
|  | 窗口收窄到正文最小值时，界面是退场而不是叠上正文 | `RG-MF-25` |
|  | 输入卡不可见时浮层不占交互区域 | `RG-MF-26` |
|  | 同一片空间多家共存时后到者收敛 | `RG-RC-27` |
|  | 同一份信息没有在中栏和右栏各放一份 | `RG-RC-28` |
