# 10 设计原则

> 判断「这样设计对不对」时用得上的原则，以及八条能被检查的视觉质量标准。原则来自 Apple 与华为的官方指南，标准来自本仓库对自家站点的要求。

## 任务

- 在没有细则可查时，用原则做出取舍
- 用八条可检查的标准审自己的界面，而不是靠「看起来还行」
- 知道哪些外部指南的东西不能搬过来

## 一、可迁移的原则（外部指南借鉴）

每条都只借判断方式，不借平台数值。出处为官方数据接口正文（Apple）与官方设计指南文档接口（华为），均为 2026-10-02 抓取，详见文末。

**定位与取舍**

1. 先想清楚做给谁、为什么做，再谈功能数量；清晰用途优先于功能多。 `[外部指南借鉴]`
2. 不挡路：能一步到位就不要加中间层。 `[外部指南借鉴]`
3. 不把人锁在固定流程里；必须引导时，要能跳过或退出。 `[外部指南借鉴]`
4. 把「可撤销 / 可回到上一状态」当基础能力，而不是附加功能。 `[外部指南借鉴]`
5. 只用真正需要的数据，并说清为什么用它。 `[外部指南借鉴]`

**一致性与结构**

6. 先沿用用户已知的概念与模式，再谈创新。 `[外部指南借鉴]`
7. 一旦确立某个元素的行为或外观，就在整个产品里一致地应用。 `[外部指南借鉴]`
8. 结构要能被一眼读懂：层级清楚、位置可预期，用户才知道自己在哪、下一步是什么。 `[外部指南借鉴]`
9. 简化不等于极简：留下重要的，删掉其余的。 `[外部指南借鉴]`
10. 文案短到刚好；能更少字就更好。 `[外部指南借鉴]`
11. 一致性本身就是可访问性：用一致、可预期的交互降低记忆负担，优先系统既有行为而不是自定义手势。 `[外部指南借鉴]`
12. 同类元素保持一致以降低学习成本，不同使用环境允许差异——差异要有理由，不是随手画。 `[外部指南借鉴]`

**反馈与状态**

13. 重要信息不要只靠单一通道传达（颜色、声音、动画都不能是唯一手段）。 `[外部指南借鉴]`
14. 反馈强度要匹配信息的重要程度，否则警报会失效。 `[外部指南借鉴]`
15. 状态放在它所描述的对象附近，让人不必离开当前上下文。 `[外部指南借鉴]`
16. 目标动作应在后台完成；必须等待时先给占位内容，而不是空白——空白会被读成「坏了」。 `[外部指南借鉴]`
17. 进度要均匀准确；5 秒到 90%、再花 5 分钟到 100% 会让人觉得被欺骗。 `[外部指南借鉴]`
18. 静止的进度指示会被当成卡死；卡住时要给解释和可采取的行动。 `[外部指南借鉴]`
19. 进程可以安全中断时才给「取消」；中断有代价时补确认。 `[外部指南借鉴]`
20. 成功的动作不必反复确认，只在失败时打扰。 `[外部指南借鉴]`

**动效与适配**

21. 没有信息量就不要加动效，也不要让人为了等动画而等。 `[外部指南借鉴]`
22. 运动要少而短：元素越多、路径越长，用户等得越久。 `[外部指南借鉴]`
23. 按可用空间决定布局，不按设备型号或方向；空间变了，功能不能变，只能改变可见量。 `[外部指南借鉴]`

## 二、八条可检查的视觉质量标准 `[本仓库建议]`

每条都写成「判据 + 检查动作 + 判定」。站点自己按这套标准做（`npm run build` 与 `npm run audit` 覆盖其中一部分），插件也可以照此自查。

| # | 判据 | 检查动作 | 判定 |
| --- | --- | --- | --- |
| V1 信息层级 | 一屏之内能分出主标题、次标题、正文、辅注四层，且最多四层 | 眯眼看一遍：能不能在 3 秒内指出「这页最重要的一句话」 | 指不出，或出现第五层字号 |
| V2 阅读宽度 | 正文行宽落在 45–90 字符之间（中文按 30–45 字） | 量正文容器的内容宽与当前字号，算每行字数 | 超出区间（太宽来回跳行、太窄频繁换行） |
| V3 密度 | 同一列表里行高一致、行距倍数一致；相邻两行之间的视觉间距误差 ≤1px | 量相邻同级元素的盒子间距集合 | 间距值不唯一（手写 margin 的典型症状） |
| V4 对齐 | 同层级元素的左/右边缘落在同一条轴线上；图标、文字、控件沿明确轴对齐且比例相称 | 量它们的 left / right / 基线 | 出现「对不齐任何东西」的孤例，或图标明显重于相邻文字 |
| V5 主题对比 | 浅色与深色两套主题下文字都达标：≤17pt 文本 ≥4.5:1，≥18pt 或粗体 ≥3:1，非文本 UI ≥3:1 | 在两种主题下各算一遍对比度（计算色值，不靠肉眼） | 任一主题不达标；只在浅色下验过也算不达标 |
| V6 交互反馈 | 每个可交互控件都有 default / hover / active / focus-visible / disabled 五态（官方控件未提供的状态不自行补） | 逐个走一遍，或扫描计算样式 | 缺态；或靠整体降透明度伪装 disabled |
| V7 焦点可见性 | 所有可交互元素可 Tab 到达，焦点环完整可见、不被 `overflow: hidden` 裁剪，顺序与视觉顺序一致 | 只用键盘走一遍整页 | 焦点丢失、被裁、或顺序跳跃 |
| V8 动效偏好 | `prefers-reduced-motion: reduce` 下位移动效停止或即时完成；循环动画只用于表达「正在进行」 | 打开系统减少动效后重看 | 大位移仍在动；或无关进程的循环动画还在转 |

补充两条来自运行时实测、必须写进验收里的 `[已知偏差]`：

- 浅色白底下 `--dsw-alias-label-tertiary` 约 **3.7:1**，低于 4.5:1，而 13px 说明与 10px 状态标签用的正是它（来源：`spec/60-accessibility.md`，站点演示 `a11y-board` 里现算）。**不要**据此覆盖官方控件；插件自己的关键信息不要只放三级色。
- 圆角口径曾在本仓库记错：此处一度写「官方 Button 自身用 r18 / r14」，那是 `%DSH_HOME%/profiles` 里过期 primitives 副本的值。产品实际加载的 `app.asar` 内 `Button.module.css` 用的是 `--dsw-radius-md`（12px）与 `.sm` 的 `--dsw-radius-sm`（8px），与官方 `docs/ui-radius.md` 的六档一致。结论不变且更硬：**新写的界面一律取 4/8/12/16/20/28 档位值**。

## 三、不能搬过来的东西

| 类别 | 例子 | 为什么 |
| --- | --- | --- |
| 物理 / 像素尺寸 | Apple 的 pt 与安全区数值、华为的 vp / fp 与 8vp 网格 | 那是特定平台硬件的换算结果；可迁移的是「字号必须随用户设置缩放」这类判断 |
| 形状与曲率 | App 图标形状、连续曲率、品牌圆角 | 形状是品牌与设备语言的绑定物；DSH 有自己的一套圆角档位 |
| 手势与硬件输入 | 侧边返回手势、表冠 / 遥控器走焦、Digital Crown | 桌面 Web 宿主里不存在或映射不同；可迁移的是「同一意图要有多种可达路径」 |
| 系统组件名与 API | `ButtonStyleMode`、`controlSize`、`UILayoutGuide` | 换宿主就错；可迁移的是「用语义接口而不是裸参数」这条纪律 |
| 颜色数值与品牌色 | iOS 系统色表、MartialColor、鸿蒙黑体 | 颜色值属于宿主主题；可迁移的是「颜色要有语义角色、要有浅深两套、要用对比度校验」 |
| 平台专有形态 | 折叠屏悬停态、挖孔区、Dynamic Island、visionOS 沉浸 | 属于特定硬件；应抽象成「宿主可能提供的容器变体」 |
| 移动端假设 | 屏幕密度、底部页签、compact 宽度 | 宿主是桌面窗口：没有密度、没有页签、宽度由拖拽决定 |

## 四、这套标准怎么用

1. **先看原则**判断取舍（该不该有这个东西）。
2. **再用 V1–V8** 检查做出来的样子（能不能过）。
3. **最后用 `40 自检与来源` 的清单**过一遍工程项（有没有硬编码、有没有漏态、有没有无限动画）。
4. 遇到官方界面自身不一致的地方（上表两条），记入 `[已知偏差]`，**不要顺手改官方控件**——覆盖官方几何本身违反控件规范。
