# 扩展位置选择：先决定放哪

> 一个界面应放在能解释它与宿主关系的区域。先判断这是全局偏好、主流程内容，还是当前会话的辅助视图，再选座位与控件。

## 读完这一页要能做什么

- 为插件功能选一个合适的 DSH 区域。
- 区分设置页、会话区浮层、宿主右栏和左侧栏。
- 说明某个扩展位置属于产品现状、公开座位，还是具体插件自己的实现。

## 先问四个问题

1. **它对所有会话都生效吗？** 是全局偏好时，优先进入设置；只影响当前会话时，留在会话区域。
2. **用户改的是一个值，还是一整组配置？** 一个全局偏好通常只需通用设置中的一行；多组配置才需要设置页分区。
3. **它必须一直看得见吗？** 只有随当前会话变化、需要持续查看的辅助内容，才考虑会话内的常驻区域。
4. **它是查看信息，还是完成主流程？** 右栏可折叠，主流程动作不能只放在那里。

## 全局偏好与当前任务选项

Apple HIG 提供一个有用的跨平台审阅问题：这是会跨任务保留的应用偏好，还是只影响当前任务的操作？当前任务的筛选、显示/隐藏或排序，应靠近受影响的内容；全局偏好再进入设置页。[外部指南借鉴] 这是审阅方法，不是 DSH 扩展 API 或强制规则。

在 DSH 插件中，先看偏好是否跨会话生效，再查适合的公开座位。不要仅为当前视图的一项临时状态添加 `settings.general.item`；视图内入口仍须由已公开的座位支持。

## 按关系选区域

选区域之前先看一屏：左栏六段、中栏四段、右栏打开后是什么、以及哪四处官方根本没有给座位，都在 [区域地图](../spec/05-region-map.md) 里。这张地图回答的是「你打算动的那块地方，官方到底有没有给它一个名字」——有名字的按座位表办，没名字的走 `guides/31`。跳过这一步的人会把「我选错了座位」和「这里根本没有座位」混为一谈。

| 要显示的内容 | 优先考虑 | 不要这样做 |
| --- | --- | --- |
| 一个全局偏好，例如语言或外观 | `settings.general.item`，作为通用设置中的一行 | 为一个值新增整页菜单 |
| 多个互相关联的设置组 | `settings.section`，增加宿主设置页中的一个分区 | 再套一层自制设置窗口 |
| 对象、工作区或会话导航 | `sidebar.panellist`、`sidebar.workspaces` 的公开子座位 | 替换整个 `sidebar` |
| 当前会话里的主要内容视图 | `conversation.session` / `conversation.view` | 放进只用于辅助查看的右栏 |
| 当前会话的浮动辅助内容 | 检查 `conversation.input.overlay` 等公开会话座位与其用途 | 把对话区内的插件浮层称为宿主右栏 |
| 临时查看上下文、文件或预览 | `rightbar.session` 下的公开页签座位 | 再造一个侧栏 |
| 独立插件设置窗口 | 当前公开座位表没有专用的独立窗口座位 | 把 `shell.overlay` 当成新窗口 API |

## 一个真实插件布局例子：dsh-widgets

`dsh-widgets` 把工具栏开关注册在 `conversation.session.header.utilities`，把右侧统计轨注册在 `conversation.input.overlay`，并把会话统计放在 `conversation.composer.dock`。它的轨道跟随主对话列的边缘；它不是 `rightbar`，这些统计卡也不是 DSH 自带控件。[插件示例]

这里有一个需要说清的边界：`conversation.input.overlay` 的公开用途描述为“在常驻输入卡内部显示浮动内容”；`dsh-widgets` 用 CSS 把这个会话级入口摆成对话区域内贴靠的面板。它证明一种插件实现，不代表宿主保证所有插件都可以把该座位当成通用侧栏。[官方源码] / [插件示例]

真正的宿主右栏是独立列 `rightbar`；其会话内容由 `rightbar.session` 管理，追加页签使用 `sidebar.right.pane.tab` 与对应标题座位。两个位置在层级、可见条件和折叠行为上不同。

## 独立窗口不是默认选项

官方公开座位表中有宿主设置分区、会话页签、会话浮层和右栏页签，没有名为“插件独立设置窗口”的座位。插件需要更多设置时，先用 `settings.section`；内容属于当前会话时，按公开的 `conversation.*` 座位选择。只有宿主明确公开对应 API 后，才能把独立窗口写成可用方案。[待核对]

## 交付前核对

- 页面里的每个标签和控件，都能在本地干净截图、官方源码或明确标注的插件示例中找到依据。
- 区域图里的注释放在窗体之外；真实 UI 窗体里只出现产品现有文字。
- 右栏、对话区浮层、左栏菜单和设置窗口分别命名，不凭屏幕坐标把它们合并。
- 来源不够时隐藏 HTML 状态示意，说明还缺哪种实景。

控件层级与尺寸见 [一屏区域地图](../spec/05-region-map.md)、[主页面骨架](../spec/10-frame-layout.md)、[控件规范](../spec/20-controls.md) 和 [可访问性](../spec/60-accessibility.md)。

## 依据

- `data/slots.json`：座位类型、作用域、替换风险与公开用途。
- `dsh-widgets/src/client/index.ts`：该插件的实际座位注册；这是插件实现，不是 DSH 原生组件。
- `docs/reference/clean-capture/`：只含隔离 profile 的产品截图；会话页签在空白会话中不会出现。
