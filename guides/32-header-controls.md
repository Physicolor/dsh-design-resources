# 会话头部右上角与会话尾部的按钮

> 在会话头部右上角和会话尾部动作行里加按钮：语义选哪个座位、图标与命中区多大、order 取多少、打开与收起该怎么动。

## 读完这一页要能做什么

- 在右上角的三个位置里选出正确的那个，并说出另外两个为什么不对。
- 给一枚图标按钮定好尺寸、形状与五个状态，包括开关型按钮的语义状态。
- 按现有占用者算出自己该取的 order，而不是随手填 0 或 40。
- 判断一个动作属于「整轮」还是「某条消息」，放进对应的座位。
- 按骨架实现打开与收起的动效，避免挤压过程中边缘脱开。

## 右上角有三个位置，语义不一样

它们都在会话头部的右侧，长得也像，但官方给的用途完全不同。选错的时候界面照样能出来，出问题的是「旁边那一枚按钮该不该在这里」这类判断。

| 座位 | 官方用途（译） | 放什么 |
| --- | --- | --- |
| `conversation.session.header.actions` | 标题旁边的会话动作 | 与这个会话本身有关的动作：重命名、分享、导出 |
| `conversation.session.header.utilities` | 右对齐的会话工具，按升序排列 | 视图级工具：面板开关、摘要开关、更多操作 |
| `conversation.session.header.corner` | 工具行边缘之外、进入头部自身内边距的最右角，**给一个控件** | 已经被右栏开关占着，不要动 |

- `RG-MF-30`：要加一枚工具按钮，进 `conversation.session.header.utilities`；只有在它描述的是「这个会话本身」时才进 `conversation.session.header.actions`。判定：把它从头部拿掉之后，用户还能不能正常读这个会话——不能，就是 actions；能，就是 utilities。[本仓库建议]
- `RG-MF-31`：不要注册 `conversation.session.header.corner`。它是 `single` 且已被右栏开关占用，而 `single` 座位不存在共存，占用等于遮蔽官方主流程入口（`SL-MF-09`、`SL-MF-10`）。[官方源码]

举一个具体例子：想在右上角加一枚「切换置顶摘要」的开关。它切换的是当前会话里的一块面板，不影响会话本身，所以进 `conversation.session.header.utilities`，不进 actions，更不能去 corner 把右栏开关挤掉。

### 一个走完全程的例子：切换置顶摘要（按钮 + 卡片 + 动效）

**① 放哪：按钮与卡片是两件事，分两个位置**

| 东西 | 放哪 | 依据 |
| --- | --- | --- |
| 开关按钮 | `conversation.session.header.utilities`（会话头部右对齐工具行） | 它不影响会话本身，`RG-MF-30` |
| 摘要卡本体 | 中栏正文右侧的留白带（官方没有座位，借道实现） | [区域地图](../spec/05-region-map.md) 第 5.1 节；借道写法见 [官方没有座位的位置](31-unofficial-regions.md) |
| 卡片的开合状态 | 挂在当前会话上，换会话即重算 | 中栏的一切随会话走（`RG-MF-17`） |

**为什么卡片不放右栏**：右栏是页面第 4 列、最窄 300px、中栏为它让路；留白带是正文居中之后的余数、可以缩到 0。摘要要「边读正文边看」，也随当前轮次变，所以它属于中栏（`RG-MF-16`）。

**② 长什么样：宽度是算出来的，不是拍的**

正文阅读列固定 **748px** 居中，中栏 1085 / 1290 宽时，两侧各剩：

```
余量（每侧） = (中栏宽 − 748) ÷ 2 = (1085 − 748) ÷ 2 ≈ 168px   （装插件栏时 1290）
```

这就是留白带的全部家当。卡片不能吃掉正文，所以：

- `RG-RC-50`：贴在留白带上的卡片宽度取 `min(273px, 余量 − 32px)`，且不低于 **240px**；低于 240px 时**折叠回会话头部**（三选一里的第一种），不要继续压榨宽度。[本仓库建议]
- `RG-RC-51`：卡片表面沿用 [Card](../components/surfaces/Card/SPEC.md) 的贴地卡片档——圆角 `--dsw-radius-xl` 20px、底 `--dsw-alias-bg-layer-2`、高程 `--dsw-elevation-soft`；**不要**自造阴影或描边。[本仓库建议]
- `RG-MF-52`：卡片不得改变正文宽度。它是浮在留白带上的，不是把正文挤窄的新列。[本仓库建议]

**③ 怎么动：什么在动、什么绝对不动**

这个例子里只有**一个**东西在动——卡片自己。留白带不动、正文不动、工具按钮不动。

| 属性 | 取值 | 为什么 |
| --- | --- | --- |
| 时长 | **300ms**，开与关相同 | `MO-RC-01` 的「较大区域进入」档；进出对称是 `MO-RC-03` |
| 曲线 | `cubic-bezier(0.40, 0, 0.20, 1)` | `MO-RC-04` |
| 动的属性 | `opacity` + `transform: translateY(4px)` | `MO-RC-08` 禁止动布局属性 |
| 不动的属性 | `width` / `padding` / `margin` | 一旦动它们，正文会跟着重排 |
| `prefers-reduced-motion` | 位移归零，只留透明度 | `MO-RC-09` |
| 关闭时 | 走完过渡再卸载，不瞬间 `display:none` | 否则用户看到「啪」一下 |
| 宽度不够时 | 卡片折叠回工具行，不是缩成一条 | `RG-RC-50` 的零宽度行为 |

按钮本身：`aria-pressed` 表达开/关（`RG-MF-34`），图标取 16 × 16、命中区 28 × 28、圆角 8（`RG-MF-32`）。

**④ 交付前对着这张表核（自检）**

| 是 / 否 | 判定项 | 条文 |
| --- | --- | --- |
|  | 按钮在 `utilities`，不在 actions、不在 corner | `RG-MF-30`、`RG-MF-31` |
|  | 卡片借道留白带，README 写明「官方无此座位」 | `RG-MF-20`、`RG-MF-25` |
|  | 卡片宽度按余量算，且没有改变正文宽度 | `RG-RC-50`、`RG-MF-52` |

|  | 过渡没作用在 `width` / `padding` / `margin` 上 | `MO-RC-08` |

## 尺寸、形状与状态

实测值来自采集（视口 1570 × 905）：

| 部位 | 实测 |
| --- | --- |
| 顶栏字形图标 | **16 × 16**，按钮命中区 **28 × 28** |
| 会话头部 chip | 容器高 **28**；图标 **14 × 14**；标签 **12 / 16** 三级色 |
| 会话尾部消息动作按钮 | **28 × 28**，圆角 **8** |

- `RG-MF-32`：右上角图标按钮的命中区不小于 28 × 28；图标本身取 16 × 16；圆角只从 4 / 8 / 12 / 16 / 20 / 28 里取（依据 [20 控件](../spec/20-controls.md) 与 [60 可访问性](../spec/60-accessibility.md)）。[运行时实测]
- `RG-MF-33`：五态齐备——默认、悬停、按下、键盘焦点可见、禁用。官方控件本身缺某个状态时如实留空，不要自己补样式（[总览 4.1 节](../spec/00-overview.md)）。[本仓库建议]
- `RG-MF-34`：开关型按钮必须带 `aria-pressed`（或语义等价物），并且图标或形状要有可见的开关差异——只靠颜色区分开与关，色觉障碍用户读不出来。[本仓库建议]
- `RG-MF-35`：图标按钮必须有可读名称；焦点环不得被头部容器裁切。[本仓库建议]

[外部指南借鉴] Apple HIG 把工具栏项与它作用的视图绑定，并要求同类工具保持一致的视觉重量；华为的设计指南建议按钮按用途、视觉类型与状态三类组织，而不是按尺寸排。这两条判断可以借，平台数值不能借：DSH 是三条各自全高的轨道、chrome 按列拥有、没有全局顶栏，所以「工具栏」在这里指的是**某一条轨道自己的头部**，一排按钮的归属由它属于哪条轨道决定，而不是由它长得像不像工具栏决定。

## order 怎么取

`conversation.session.header.utilities` 是 `list` 座位，官方实测有 4 个占用者，order 分别是 **-10 / -5 / 未声明（落在默认 0）/ 5**。这是全仓库里顺序最可解释的一个座位，别把它弄乱。

- `RG-MF-36`：新增 entry 取该座位当前最大 order + 10。按上面的实测值，今天应从 **15** 起；写完在你的 DSH 上重新核对一次，因为占用者数量取决于装了哪些插件。[本仓库建议]
- `RG-MF-37`：不要取 0。0 是留给官方既有项的区间，插件取 0 等于把自己插进官方的相对顺序里，而那个顺序不是你定的。[本仓库建议]

分段表（完整说明见 [座位目录与选择](../spec/11-slot-seats.md) 第 3 节）：

| 区间 | 用途 |
| --- | --- |
| ≤ -10 | 框架级、主流程前置项 |
| -9 .. -1 | 优先级前置 |
| 0 | 官方既有占用 |
| 1 .. 99 | 常规新增，按 +10 递增 |
| ≥ 100 | 保留 |

- `RG-MF-38`：同一插件在同一座位的相邻 order 间隔 ≥ 5，且不超过 3 个 entry。超过 3 个说明这个座位被当菜单用了，应该改用自带弹出层。[本仓库建议]

## 会话尾部的动作行

截图中一轮回答左下角那一排小图标（复制、插入、撤销之类）和右下角的评价按钮，都是同一个机制：**一轮完成之后渲染的动作行**。

| 座位 | 官方用途（译） | 放什么 |
| --- | --- | --- |
| `conversation.chat.turnTail` | 在一轮完成后的动作行**之前**的有序特性贡献 | 针对整轮的东西：用时、统计、这一轮的摘要入口 |
| `conversation.chat.assistant-actions` | 针对一条**已定稿的助手消息**的有序动作 | 复制、引用、重试、评价这类针对消息本身的动作 |

- `RG-MF-39`：动作的对象是整轮就进 `conversation.chat.turnTail`，是那条消息就进 `conversation.chat.assistant-actions`。反例是把「这一轮用了多久」放进消息动作行——它不属于任何一条消息，换一条消息它还是那个数。[本仓库建议]
- `RG-MF-40`：动作行里可见控件不超过 6 个（`FL-RC-05`）。超出时收进菜单。[本仓库建议]
- `RG-MF-41`：这些动作行是 `list` 座位，同样要显式声明 order 并取现有最大值 +10。[本仓库建议]

## 左栏左下角：设置入口与可追加的动作区

右上角讲完之后，另一处被问得最多的是「左下角那排小图标」。左栏底部其实是**两段**，别把它们混成一段：

| 位置 | 官方座位 | 实测几何（1570 × 905 视口，[来源](../docs/reference/geometry.json)） | 能不能追加 |
| --- | --- | --- | --- |
| 底部工具行本体 | 无座位（外壳自己画） | `settingsArea` **256 × 42 @ (12, 857)**，距窗口下沿 **6**；行内触发层 **260 × 34 @ (10, 861)** | 否 |
| 设置入口 | `sidebar.settings`（宿主 `single`） | 在上一行的左侧；图标取 **16 × 16**、命中区 ≥ **28 × 28** | 否 |
| 设置右边的扩展动作区 | `sidebar.footer.action`（`list` / root，**可追加**） | 与设置入口同行；干净 profile 下渲染为空 | 是 |
| Desktop 账户入口 | `settings.launcher`（`single` / root） | 只有 Desktop 外壳占用，Web 采集里看不到 | 否 |

左栏顶部另有一处**控制图标**，它不属于左下角：品牌行右端的面板折叠开关（`sidebar.brand.mark` 那一行的右端），实测 **12 × 12** 字形、命中区 ≥ 28 × 28，作用是收起整条左栏。

- `RG-MF-45`：加在 `sidebar.footer.action` 的控件与设置入口**共用同一行、同一垂直中心线**；图标取 16 × 16、命中区 ≥ 28 × 28、圆角从允许的六档里取（与 `RG-MF-32` 同一组尺寸）。[运行时实测]
- `RG-MF-46`：该区的间距、行高与对齐由外壳统一管理，插件只贡献单个图标控件（`RG-MF-02`、`FL-MF-09`、`SL-MF-13` 是同一条纪律的三处表述）；缺省状态下不要自己画分隔线或底板，否则插件一装上就会看出「这里贴了一块不一样的」。[本仓库建议]
- `RG-MF-47`：图标按钮必须有可读名称——只画一枚图形、没有 `aria-label` 也没有可见文字时，这个入口对读屏用户等于不存在；提示气泡的几何与出现时机走 [控件规范 7.3 节](../spec/20-controls.md)，不要另造一套。[本仓库建议]

## 打开与收起：动效骨架

摘要卡这类「点一下打开一块面板」的动效，按下面五步走。具体时长与曲线档位见 [40 动效](../spec/40-motion.md)。

1. **先定谁在动。** 只让卡片自己淡入位移，还是同时让中栏让位？如果卡片占掉中栏的一部分宽度（例如贴在正文右侧的摘要卡），那就是两个东西同时在动。
2. **两个一起动时，必须读同一组时长与缓动变量。** 否则挤压过程中两者进度不同，边缘脱开、内容跳一下（`RG-MF-18`）。
3. **不要动 `width`。** 宽度过渡会持续触发布局重算，在长会话里肉眼可见地掉帧。要腾空间就动 `padding` 或 `margin`，并让两边引用同一个变量。
4. **关闭时不要瞬间移除。** 正在退出的元素被 `display: none` 掉，用户看到的是「啪」一下消失。让它走完自己的过渡再卸载。
5. **`prefers-reduced-motion` 下必须降级。** 位移与缩放取消，只保留一次性的透明度切换。

- `RG-MF-42`：打开与收起的两侧必须引用同一组时长与缓动变量，不得各写一套数值。[本仓库建议]
- `RG-MF-43`：过渡不得作用于 `width` / `height` 这类触发布局的属性；必须给空间时改 `padding` / `margin` 并让占位方与轨道同步。[本仓库建议]
- `RG-MF-44`：`prefers-reduced-motion` 下取消位移与缩放，保留淡入淡出。[本仓库建议]

**具体数值（2026-10-06 冻结）**：展开与收起都取 **300ms**（[动效](../spec/40-motion.md) 五档里的「较大区域进入：面板、侧栏、浮层出现」），曲线用标准曲线 `cubic-bezier(0.40, 0, 0.20, 1)`（`MO-RC-04`）；进出对称是 `MO-RC-03` 的硬要求，所以「收起比展开快一点」这种手感调整在这里不成立。把这两个值写成你自己的局部变量再被两侧引用——占位方与浮层各自硬编码一份数值，就是 `RG-MF-42` 要判的缺陷。降级用 `MO-RC-09`：`prefers-reduced-motion: reduce` 下位移与缩放归零，只保留一次透明度切换，状态切换本身不省。

[已知偏差] 有两处既成事实与上面这组数值不一致，引用时别把它们当范例：`components/controls/Switch/switch.module.css` 第 21 行是 `--dsh-switch-duration: 120ms`（不在五档内，而 `MO-RC-01` 给这类小元素状态切换的档位是 150ms），`components/feedback/InlineNotice/inline-notice.module.css` 第 38 行是 `160ms ease-out`（既不在五档内，也不是标准曲线）。这两处是组件实现里的遗留值，本轮不改实现，登记在此以免下一个作者照抄。

## 反例

- **把开关放进 `conversation.session.header.corner`**：那里只有一枚控件的位置，且已被右栏开关占用；你挤掉的是用户打开右栏的唯一入口。
- **用 `aria-pressed` 表达「面板已打开」但按钮其实是个链接**：语义状态只有真正的按钮或开关才成立，链接要用 `aria-expanded`。
- **打开面板时把焦点抢过来**：用户按下的是一枚工具按钮，焦点应该留在那里或移到面板内的第一个可交互元素，而不是随手飘到面板某个角落。
- **同一件事同时挂在 `utilities` 和 `turnTail`**：用户会看到两枚同样的按钮，一枚管整个会话，一枚管这一轮。
