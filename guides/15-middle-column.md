# 中栏能不能被单独使用

> 判断一份内容该占满中栏、该进会话页签，还是只做中栏里的一条浮层带；以及它为什么不该被放进右栏。

## 读完这一页要能做什么

- 说出中栏的三种用法，以及每种用法下用户还能不能看到对话正文。
- 用判定流程把一个具体功能放进正确的档位，而不是挑名字最像的座位。
- 认出走在错档位上的界面会怎样坏掉，并知道该换到哪一档。
- 用五条可测量的差别回答「放中栏还是放右栏」，不靠视觉偏好。
- 说清文件树和终端为什么不属于中栏。

## 先说结论：中栏有三种用法

你写了一个插件面板，它得放在中栏。下一个问题是它跟对话正文的关系是什么，因为中栏不是只有一个位置。

- **占满中栏**：左栏有一个入口图标，点开之后中栏整页换成你的面板。用户要离开当前会话才能看它。
- **进会话页签**：会话头部那排「对话 / 轨迹 / 上下文」是可以追加的。进去之后一次只显示一个视图，用户此刻看不到正文。
- **留在中栏里**：输入卡上方、下方或内部的一条带。它和正文同屏，跟着当前轮次变。

三种用法不是大中小，而是三种关系。选错的代价不是难看，是功能不成立。

**把需要边读正文边看的东西做成页签，用户就得在两个页签之间来回切。** 这不是风格问题：页面一次只渲染一个视图，用户物理上看不到两样东西。

**把与任何会话无关的工作台塞进那三条带，用户换个会话它就没了。** 中栏里的一切都随当前会话走，这是作用域决定的，不是实现细节。

## 你的内容属于哪一种

按顺序问，第一个「是」就是答案。

1. **它离开会话依然成立，用户也愿意为它离开当前会话？** 占满中栏：注册一个 `main` 面板，在左栏 `sidebar.panellist` 放一个入口图标。插件列表、报告页、配置中心属于这一类。
2. **它是同一个会话的另一种看法，和正文互斥？** 进会话页签：注册到 `conversation.view`。轨迹、上下文、审查、导出预览属于这一类。
3. **它要与正文同屏，并随当前轮次或当前输入变化？** 留在中栏里：常驻的用 `conversation.input.dock`（输入卡上方）或 `conversation.composer.dock`（输入卡下方）；只有补全、下拉、提示这类瞬时 UI 才用 `conversation.input.overlay`。
4. **它必须始终可达，或者要跨会话常驻？** 它不属于中栏，去右栏。
5. **它其实只是一项偏好或一组设置页？** 去 [设置页模式](20-pattern-settings.md)。
6. **全否**：它不该待在这一屏上。

第 4 问是最容易答错的一问，下一页专门讲它。

## 中栏还是右栏：五条能测的差别

「哪个更好看」答不了这个问题。下面五条是能测的，全部来自官方数据与官方源码。

| 问 | 中栏里的那条带 | 右栏 |
| --- | --- | --- |
| 它是什么 | 正文居中之后剩下的余量 | 页面的第 4 列 |
| 宽度谁定 | 算出来的余数，可以是 0 | 自己定，最窄 300px |
| 谁给谁让路 | 官方没排过序，正文到底线它就消失 | 右栏先缩，然后失去轨道，最后才轮到中栏 |
| 多家怎么共存 | 同一块地方的多个固定层，没有页签 | 各占一枚页签 |
| 活多久 | 跟会话内容一起滚 | 每个会话一个停靠面，可以钉住 |

于是有两条判据，记住这两条就够了：

- **必须始终可达、不能随窗口变窄消失的，放右栏。** 中栏那条带会先没。
- **要跨会话常驻、或者要钉住另一个会话的，放右栏。** 中栏的一切都跟着当前会话。

宽度那条更值得单独记住：右栏有 300px 的下限，中栏那条带没有下限。这就是为什么把要紧的东西放在带里，用户在窄窗口上会突然找不到它。

## 为什么文件树和终端不该放这里

它们是最常被塞进中栏右侧留白带的两种东西，两次都错，错因还不一样。

- **文件树要自己的滚动量级和展开层级。** 用户会长时间盯着它、来回点。它过不了「让路」这条：留白带在窗口变窄时先消失，而文件树既不能消失也不能缩成 0。
- **终端要活过会话切换。** 它过不了「活多久」这条：中栏的一切都是当前会话的。

它们不是没地方放，是**地方在右栏**。干净 profile 的空白会话右栏开始页上就有「工作区文件」和「新建终端」两项宿主操作，右栏也给文件树和文档预览留了页签内的动作位。去中栏给它们找位置，是在解决一个不存在的问题。

## 开合的时候，边缘为什么会对不齐

留白带是可折叠的。展开时它占掉中栏里的一段宽度，正文相应让位；收起时那段宽度还回去。看起来只要写两个过渡就行，实际不是。

**占位方和轨道必须读同一组时长与缓动。** 如果占位方用 200 毫秒、轨道自己的过渡用 150 毫秒，挤压过程中两者的进度不一样，用户会看到边缘脱开、内容在收起的一瞬间跳一下。做法是把时长与曲线提成同一个自定义属性，两边都引用它，别在一边写死数值。

官方控件自带过渡的那些地方优先沿用官方值，别为了统一去覆盖它们。

## 一个真实例子：会话统计轨

`dsh-widgets` 把它那条会话统计轨放在中栏右侧的留白带上，借的座位是 `conversation.input.overlay`。按上面的流程，它的档位选对了——统计随会话变化、要与正文同屏、消失也不影响主流程，三条都符合「留在中栏里」。

但它同时也说明了借道的代价：那条留白带官方没有座位，所以这条轨道能不能出现，取决于借来的座位在下一版里被怎么对待。借道的写法、声明方式与降级要求见 [官方没有座位的位置](31-unofficial-regions.md)。[插件示例]

| 是 / 否 | 判定项 | 条文 |
