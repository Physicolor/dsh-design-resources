# 设置页模式：从一项偏好到完整分区

> 设置先解决全局偏好。选择放置层级后，再选控件；宿主设置窗口、插件设置页和独立窗口是不同的概念。

## 读完这一页要能做什么

- 判断设置项应进入通用设置，还是需要在设置菜单里增加一个分区。
- 复用 DSH 通用设置页真实存在的下拉选择、外观选项、数字调节、开关与动作按钮。
- 确认插件是否有公开的独立窗口扩展点；没有时不要虚构窗口 API。

## 通用设置里的一项偏好

当设置是一个全局偏好、只需要一行时，使用 `settings.general.item`。它是设置分区内的追加座位；官方示例包括 Language、Appearance 与 Composer Enter。适合开关、短选项或单个有范围的数值。

隔离 profile 截图中可以看到真实的「语言」「外观」「显示代码工作视图」和「字号大小」行。下面的示意抽取一项真实设置行；旁注说明何时该选择这种结构。窗内只保留产品实际出现的文字。

## 需要独立的设置页时

当设置分成几组、用户需要从菜单进入某一页时，使用 `settings.section`。每个 list entry 对应设置窗口中的一个页面，窗口、导航列和内容列仍由 DSH 宿主提供。插件页不再另套一层完整设置窗口。

干净截图中的「模型」页用于说明宿主页面结构。它是 DSH 自带页面，示意没有把插件自造的菜单名称或内容混进去。

## 独立插件窗口的边界

当前公开座位表没有专门的插件独立设置窗口座位。`settings.trigger` 与 `settings.launcher` 是宿主设置入口；`shell.overlay` 是跨区域浮动层，不能据此声称插件获得了一个独立窗口。设置仍用 `settings.general.item` 或 `settings.section`；会话相关工具按 `conversation.*` 与 `rightbar.*` 的公开用途选择。

| 界面元素 | 干净实景里的真实文案 | 适合何时使用 |
| --- | --- | --- |
| 设置导航项 | `通用设置`、`模型`、`内置插件`、`Agent 预设` | 菜单项只需清楚命名目的地；这份实景中的菜单没有描述，不添加虚构说明。 |

| 选项标题与说明 | `工作步骤展示`；`选择希望看到多少工具调用细节` | 说明只补充标题没有表达的影响或范围。 |
| 下拉选择器 | `权限`、`语言`、`工作步骤展示`；当前值如 `工作区内修改`、`中文`、`详细` | 选项较多或需要节省横向空间时；用户点击后再看完整选项。 |
| 外观选项组 | `浅色`、`深色`、`跟随系统` | 互斥的外观选项需要并排比较时。将其称为外观选项组，不把它泛称为动作按钮。 |
| 数字调节 | `字号大小`、`14 px` | 值有明确上下限或步长，且单位需要始终可见时。 |
| 开关 | `显示代码工作视图` | 立即生效的二态偏好；若操作需要保存/取消，应使用表单动作而不是开关。 |
| 动作按钮 | `编辑快捷键`、`打开配置文件` | 执行一个动作或打开后续流程，不表达一个持续的选择值。 |

## 使用边界

- 一行偏好优先用 `settings.general.item`；多组设置再考虑 `settings.section`。
- `settings.section` 是设置窗口里的页面，不是独立插件窗口，也不是主对话内容。
- 不要把 `Command Code`、组件页签或其他插件贡献页面抄成 DSH 默认菜单。
- 开关、下拉、数字调节和动作按钮各自表达不同关系，不要为了排版把它们互换。
- 内容、状态或来源没有干净实景依据时，暂缓对应 HTML，不填“示例值”来占位。
